# S08 P5 — Display, bytes and recursion

P5 starts on `codex/s08-p5`, based on P4 commit `6d78b3c`. The P4
`p4-inventory-12` capture executed all requested diagnostic phases for 9,369
acceptance and 1,359 informational variants. It did not compare exact native
baselines. Its remaining type/symbol-walker boundary belongs to this checkpoint.

## Implementation sequence

1. Expose the existing production node builder to a checker operation. Preserve
   enclosing declarations, independent builder/internal flags, native absent
   results, and the lifetime of generated syntax and emit metadata. Add the
   context-sensitive type and symbol display entry points. Check these against
   pinned Go before using them as baseline infrastructure.
2. Port the native type/symbol walk and byte decoration into the Rust harness.
   Keep native preorder, reparsed-node filters, type-before-symbol ordering,
   query flags, alias expansion, trivia positions and declaration coordinates.
   Record the actual query schedule alongside output bytes. Compare with the
   existing P0 native archive; do not replay expected queries into Rust.
3. Complete the error writer from `tsbaseline/error_baseline.go`, including
   input/auxiliary/config ordering, related diagnostics, pretty output and
   non-ASCII line handling. Keep diagnostic production separate from formatting.
4. Use source-selected cases to exercise accessibility, annotation reuse,
   computed names, emit flags and printer closure. Run the complete baseline
   inventory once the walker exists; retain every unsupported/error/absent
   result and fix concrete missing branches without changing eligibility.
5. Complete cached-builder reuse and arena rotation with retention tests.
   Add E4 checks through checker/builder/printer entry points and actual small
   stack recursion fixtures, including unwind after growth and owner retirement.
6. Record exact comparison counts and remaining failures, then open the P5 PR
   against P4. P6 owns final semantic acceptance; P7 owns performance captures.

## Contract review before implementation

- `TypeToString` alone cannot implement the native baseline writer: the writer
  calls `TypeToTypeNode` with the parent as context and `AllowUnresolvedNames`,
  then a regular text writer. It also inspects the resulting node for an alias
  retry. The API must expose that node without reconstructing it from text.
- A generated node ID must not outlive its owner. Borrowed builder views keep
  syntax and emit metadata together; retained results need explicit ownership.
- Native `NewNodeBuilder` requests and the checker's cached `getNodeBuilder`
  are different lifetimes. Implementing the former does not close the latter.
- Source bytes and harness input order are authorities. Numeric type IDs are
  capture-local identities; do not equate Go and Rust allocation numbers.
- Keep disabled, NoContent, empty content and failures distinct. Informational
  variants remain outside the acceptance denominator.
- Use focused differential cases while developing. Do not rerun the two-hour
  diagnostic inventory after each display edit or treat its execution count as
  an exact-byte parity result.
- The owner's temporary CI reduction to macOS ARM and Linux x86 remains in
  place. The supported-target policy has not changed.

### Native walker and contextual queries

The second increment implements the native type/symbol walker and its raw byte
decoration. [Nineteen focused cases](../data/s08/p5/walker/README.md), with 493
actual queries, match pinned Go's bytes and ordered requests. No expected
schedule is replayed into Rust. Disabled, NoContent, empty-file content and
failures remain distinct. A trace held outside the checker operation preserves
the failing query through a panic while the operation unwinds and retires.

The comparison exposed and fixed production query gaps:

- Contextual type-query dispatch and `getRegularTypeOfExpression` now
  handle property names, class heritage, binding patterns and declaration names
  in native order. Non-type syntax passed to the type-node worker returns Go's
  `errorType`, including an identifier within a type reference.
- Import/export property names use the cached immediate alias target. Computed
  and indexed property names resolve symbols; ordinary literal call arguments
  return no symbol. Renamed object bindings resolve the source property.
- Unresolved alias references use Go's cached intrinsic `error` type carrying
  the alias, distinct from the symbol's declared `unresolved` type. The cache is
  included in retained-type traversal and the memory census.

Review correction: selecting a native file checker does **not** force source
checking. The walker preserves `noCheck`/`skipLibCheck`; it uses the checker
state left by the requested diagnostic phases. The focused fixture explicitly
exercises both options.

`p5_inventory` shares P4's diagnostic executor, then walks the same checked
owner. P4 remains diagnostic-only and keeps its previous output contract.
`scripts/s08_baselines.py --walker-inputs` additionally observes native ordered
input/auxiliary files, mapped source bytes and the header. The bytes travel as
hex, preserving invalid UTF-8 and duplicate filenames. Neither reference
baseline text nor expected queries supplies the Rust input order.

The frozen corpus smoke set matched type/symbol bytes and all 1,048 query actions
for its three acceptance variants: `2dArrays.ts`, `accessorDeclarationEmitJs.ts`
and `overshifts.ts`. Its informational `APILibCheck.ts` remains disabled and
`moduleNoneDynamicImport.ts` remains a native option rejection. These are five
selected cases, not full-corpus acceptance. Diagnostic execution and type/symbol
parity do not establish `.errors.txt` parity.

python3 scripts/s08_p5_corpus.py --native target/s08/p5-native-new --output target/s08/p5-rust-new

### Diagnostic formatting and error decoration

The third increment adds `ts_compiler::diagnostic_writer`, backed by the
retained program's source identities. It formats existing diagnostics without
running checker queries. It supplies default-locale formatting, plain and ANSI
output, related locations, multiline code snippets and error summaries. Source
snapshots and line maps live only in the formatting request; returned snapshots
remain independently owned and cannot be mutated through the public API.

`tools/s08/p5/errors.rs` ports the separate native `.errors.txt` annotation
algorithm. Input order is an explicit argument. It preserves the native library
location substitutions, Unicode case folding, raw source bytes, message-chain
indentation, coverage assertions and NoContent state. Diagnostic arguments use
Go's explicit `ToValidUTF8` operation; external messages remain raw bytes.

[Twenty-four native fixtures](../data/s08/p5/errors/README.md) match all five
outputs per case exactly. The same comparison runs in a Rust integration test;
a separate 1,000-level message chain exercises iterative flattening on a 512 KiB
stack. This does not close P5's checker/printer stack-growth and unwind inventory.
The walker regression still passes after extracting the common path-prefix
replacement.

Two native details are recorded rather than silently normalized: the error
writer splits on CR?LF while its line map also recognizes CR/LS/PS; and fresh
external-diagnostic file wrappers count separately in pretty summaries. Equal
file names with different locations can inherit Go map-order nondeterminism.
The fixture uses identical locations for that case while retaining both entries.

The full corpus adapter still needs its error-baseline input metadata and typed,
sorted/deduplicated diagnostic aggregation wired in. Error inputs are
`tsConfigFiles + toBeCompiled + otherFiles`, with the native mapped-file filter;
the type/symbol walk instead uses source-filtered `toBeCompiled + otherFiles`.
Reusing the walker list would omit config and unloaded auxiliary inputs. The
post-emit diagnostic comparison must remain visible. Compiler diagnostics that
need content-map span translation currently return named Unsupported; they are
not rendered against the wrong text.

P5 therefore remains open: full baseline inventory/integration, any demonstrated
remaining display branches, cached builder reuse/arena rotation, E4 integration,
and the native recursion/growth/unwind scenarios. No acceptance denominator,
threshold, CI matrix or producer outcome was changed for this increment.

Validation for the third increment: the 24-case five-output native comparison,
both new Rust tests, the existing walker regression and all 13 P5 protocol tests
pass. Clippy for the changed compiler library, example and tests passes with
warnings denied. The operation inventory remains unchanged. No full corpus,
performance or instrumented ownership run was repeated for this formatter work.
