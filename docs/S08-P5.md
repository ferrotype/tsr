# S08 P5 — Display, bytes and recursion

P5 starts on `codex/s08-p5`, based on P4 commit `6d78b3c`. The P4
`p4-inventory-12` capture executed all requested diagnostic phases for 9,369
acceptance and 1,359 informational variants. It did not compare exact native
baselines. Its remaining type/symbol-walker boundary belongs to this checkpoint.

## Implementation sequence

1. Expose the existing production node builder to a checker operation. Preserve
   enclosing declarations, independent builder/internal flags, native absent
   results, and the lifetime of generated syntax and emit metadata. Add the
   context-sensitive type and symbol display entry points. Check these against
   pinned Go before using them as baseline infrastructure.
2. Port the native type/symbol walk and byte decoration into the Rust harness.
   Keep native preorder, reparsed-node filters, type-before-symbol ordering,
   query flags, alias expansion, trivia positions and declaration coordinates.
   Record the actual query schedule alongside output bytes. Compare with the
   existing P0 native archive; do not replay expected queries into Rust.
3. Complete the error writer from `tsbaseline/error_baseline.go`, including
   input/auxiliary/config ordering, related diagnostics, pretty output and
   non-ASCII line handling. Keep diagnostic production separate from formatting.
4. Use source-selected cases to exercise accessibility, annotation reuse,
   computed names, emit flags and printer closure. Run the complete baseline
   inventory once the walker exists; retain every unsupported/error/absent
   result and fix concrete missing branches without changing eligibility.
5. Complete cached-builder reuse and arena rotation with retention tests.
   Add E4 checks through checker/builder/printer entry points and actual small
   stack recursion fixtures, including unwind after growth and owner retirement.
6. Record exact comparison counts and remaining failures, then open the P5 PR
   against P4. P6 owns final semantic acceptance; P7 owns performance captures.

## Contract review before implementation

- `TypeToString` alone cannot implement the native baseline writer: the writer
  calls `TypeToTypeNode` with the parent as context and `AllowUnresolvedNames`,
  then a regular text writer. It also inspects the resulting node for an alias
  retry. The API must expose that node without reconstructing it from text.
- A generated node ID must not outlive its owner. Borrowed builder views keep
  syntax and emit metadata together; retained results need explicit ownership.
- Native `NewNodeBuilder` requests and the checker's cached `getNodeBuilder`
  are different lifetimes. Implementing the former does not close the latter.
- Source bytes and harness input order are authorities. Numeric type IDs are
  capture-local identities; do not equate Go and Rust allocation numbers.
- Keep disabled, NoContent, empty content and failures distinct. Informational
  variants remain outside the acceptance denominator.
- Use focused differential cases while developing. Do not rerun the two-hour
  diagnostic inventory after each display edit or treat its execution count as
  an exact-byte parity result.
- The owner's temporary CI reduction to macOS ARM and Linux x86 remains in
  place. The supported-target policy has not changed.

### Persistent diagnostic display cache and allocation-frame release

The diagnostic byte-returning entry points now share completed serialization
entries and emit metadata through their checker owner. Each request constructs
exclusively; successful frames containing reusable entries are validated and
published, while uncached frames are dropped. Cache hits import the retained
frame before deep cloning. The public `NewNodeBuilder` analogue retains its own
syntax and local cache until its caller drops it.

The pinned `visitAndTransformType` key includes type identity, enclosing node,
builder flags and internal flags. Object, source-backed reference, conditional
and circular-union transforms use it. Hits restore byte-length/truncation state
and replay tracked symbols; reported diagnostics and encountered errors prevent
insertion. Native nil-enclosing entries are never looked up, so Rust does not
retain those unusable entries after a request.

Cache entries own their syntax frames, which retain imported/source owners.
Emit metadata and generated-identifier associations hold non-owning IDs. After
the final nested request releases, metadata pruning checks the ownership of
both live keys and original/generated-name targets before removing any entries.
Repeated cache-hit output frames are released rather than appended to a chain
of retained generations. No checker-owning pointer is stored below the checker.

Five cache tests cover old-node and source-key survival, stable owner/allocation
counts on repeated calls, length/truncation restoration, tracked symbol replay,
generated-name/original metadata, independent explicit builders, context keys,
nested successful calls and ordinary-error/diagnostic cleanup. The real checker
operation's stack-growth panic test now uses the cached request path and checks
terminal retirement and final release. A printer test rejects metadata pruning
with a live but unretained dependency without partially pruning the tables.

The census now names `display_cache`, `display_ast` and `display_emit` as P5
families and follows serialized type keys as roots. Cache map capacity and
tracked-symbol backing are charged. AST-page bytes and standard-map/name/comment
backing in emit metadata remain explicitly unavailable; occupied entry/node
counts are reported. These are unpaired Rust families until the P7 native
measurement is extended. They must not be interpreted as zero-cost storage.

The direct native matrix is now 82 requests, including fourteen repeated object,
conditional and recursive-tuple displays across contexts and quote flags. All
82 match exactly; the existing 23-case/844-action walker comparison and 70
checker regressions also pass after caching. This is supplemental validation,
not a refreshed full-corpus count or a performance result.

Two allocation differences remain explicit. A retained frame contains scratch
constructed alongside its cached values, rather than tracing individual syntax
nodes. Also, nested calls can reuse completed published entries but cannot read

ownership tests establish safety and the native matrix establishes its tested
bytes; neither establishes identical nested cache hits or allocation counts.
P7 must include this storage and traffic, and a demonstrated schedule/semantic
counterexample must be fixed before treating this part as native-equivalent.
P5 still needs production E4 producer integration and the remaining recursion
