## Dynamic import checking

The first increment ports `checkImportCallExpression` and its grammar checker.
Previously expression checking sent `import(...)` through ordinary untyped
call resolution, returning `any`. It now checks every argument in native order,
resolves the module with its attributes, applies the existing default-only or
synthetic-default namespace wrapper, and returns `Promise<namespace>`.
Nonliteral and unresolved imports return `Promise<any>` with the appropriate
diagnostics. Missing Promise declarations use the import-specific messages.

The contextual argument path supplies `string`, `ImportCallOptions` and `any`
for the first, second and surplus arguments. Reporting and nonreporting global
lookups have separate caches, as in Go; both are included in retained-type
traversal. Quick expression checks, import-attribute extraction and inline
attribute const contexts now recognize the complete `IsImportCall` predicate,
including `import.defer`.

The grammar port preserves early returns for module-mode restrictions, type
arguments, the second argument in older modes, invalid arity and spread
arguments. Semantic checks still visit excess arguments. Parenthesized options
preserve the native attribute behavior, while the obsolete `assert` diagnostic
only inspects an original object-literal argument.

This uses the existing module resolver, namespace wrappers, Promise machinery,
owner and paged type storage. It adds no dependency, alternate checker path,
unsafe code or relaxed acceptance rule.

## Focused verification

complete semantic diagnostic payloads. They cover awaited namespaces,
attribute-discriminated pattern modules, JSON default-only exports, CommonJS
namespaces, invalid/nonliteral specifiers, argument grammar, obsolete assertions,
deferred imports with attributes, and absent Promise types or constructors.
The Rust integration test compares them with native observations and repeats
each query on the same checker owner.

The full P2 comparison additionally observes nested properties and signatures.
It matches 3/11 programs; 8 differ only in nested display fields, including
truncated `Promise.then` signatures. Those differences remain failures; the
narrower regression projection does not certify the full comparison. The
missing-global fixtures match the full P2 comparison. Native requests,
observations, sources and the fixture projection are retained in the
[P6 evidence](../data/s08/p6/README.md).

The bounded corpus recheck improves from 15 to 19 exact matches among its 22
acceptance variants; one informational variant still differs. All previous
matches remain matches, all 23 executions complete, and the captured sources
are stable. It fixes `importAttributeDynamicImports` and the three selected
`nodeModulesDeclarationEmitDynamicImportWithPackageExports` configurations.
The remaining selected differences belong to the `esmModuleExports` family.

The new regression test, clippy for checker/compiler across all targets and
features with warnings denied, the checkertext producer, formatting and ledger
validation pass. The S07 operation mappings remain unchanged. Full E2
