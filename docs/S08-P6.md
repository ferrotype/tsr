and executes the comparator/recursion obligations. Bounded smoke results do not

## Implementation sequence

1. Use the retained P5 failures to select a concrete semantic family. Compare
   the checker path with pinned Go, port the missing behavior through the
   existing owner and type stores, and add source-selected native witnesses.
   Preserve raw differences rather than changing the comparator to accept them.
2. Recheck affected frozen variants together with previously matching controls.
   Record diagnostic bytes, type/symbol bytes and actual query schedules
   separately. Keep execution failures distinct from completed-but-different
   results. A subset improvement does not update the historical full count.
3. Resolve remaining diagnostic, relation and display families from those
   comparisons. With the E2 capture/verification layer in place, run one
   complete inventory after the implementation stabilizes;
   use bounded rechecks while developing. Review diagnostic order and arguments,
   query side effects, recursive behavior and cache ownership independently.
4. Connect the exact semantic comparisons to E2 with source-bound evidence;
   retain the native runner's phase selection and the S07-3 amendment. Complete
   the S08 ownership contributors and applicable E3 instrumentation, including
   failure/reentry, retained handles and generation retirement. Audit recursion
   and approved divergences before claiming the nonmeasurement requirements.
5. Leave checkerbench, relater and footprint acceptance to P7, and the final
   coordinated producer refresh to P8. Neither a supplemental comparison nor
   a successful diagnostic execution marks E2 or S08 complete.

## Dynamic import checking

The first increment ports `checkImportCallExpression` and its grammar checker.
Previously expression checking sent `import(...)` through ordinary untyped
call resolution, returning `any`. It now checks every argument in native order,
resolves the module with its attributes, applies the existing default-only or
synthetic-default namespace wrapper, and returns `Promise<namespace>`.
Nonliteral and unresolved imports return `Promise<any>` with the appropriate
diagnostics. Missing Promise declarations use the import-specific messages.

The contextual argument path supplies `string`, `ImportCallOptions` and `any`
for the first, second and surplus arguments. Reporting and nonreporting global
lookups have separate caches, as in Go; both are included in retained-type
traversal. Quick expression checks, import-attribute extraction and inline
attribute const contexts now recognize the complete `IsImportCall` predicate,
including `import.defer`.

The grammar port preserves early returns for module-mode restrictions, type
arguments, the second argument in older modes, invalid arity and spread
arguments. Semantic checks still visit excess arguments. Parenthesized options
preserve the native attribute behavior, while the obsolete `assert` diagnostic
only inspects an original object-literal argument.

This uses the existing module resolver, namespace wrappers, Promise machinery,
owner and paged type storage. It adds no dependency, alternate checker path,
unsafe code or relaxed acceptance rule.

## Skipped grammar diagnostics, enum member parents, missing names and write access

TS1216 for an exported `__esModule` binding now goes through a port of
`grammarErrorOnNodeSkippedOnNoEmit`. The checker reports it with
`skipped_on_no_emit` regardless of `noEmit`, and program semantic selection
removes it under `noEmit`, as in pinned Go. The previous checker-level `noEmit`
gate is gone. The regression uses the `compiler/es5-commonjs8.ts` source.

Enum member display now ports `appendReferenceToType` and `getAccessStack`.
When the parent enum is reachable only through an import type, as in
`compiler/declarationEmitQualifiedName.ts`, the member extends the import
qualifier. Quoted members use a `typeof` import type with an indexed access.
A Rust-only approximate-length increment was removed. The instantiation
expression and access-expression branches of `appendReferenceToType` remain
named unsupported boundaries; the enum caller cannot reach them. The native
witness is `data/s08/p6/enum-member-display`.

`getResolvedSymbol` no longer resolves a parser-inserted missing identifier.
Focused P2 witnesses in `data/s08/p6/missing-identifier` show equal syntactic
diagnostics before the change, so parser recovery was not the cause; only the
checker added `Cannot find name '(Missing)'`.

`accessKind`, `IsWriteAccess` and `IsWriteOnlyAccess` are now ported. They
supply the name-resolution `isUse` flag, the write-only exemption in
`markPropertyAsReferenced`, the accessibility writing flag and write-type
selection, replacing assignment-target approximations. Regressions use the
pinned `compiler/noUnusedLocals_writeOnly.ts` baseline and native witnesses in
`data/s08/p6/write-access`, captured with the new program-diagnostics driver
`tools/s08/p6/semantic_diagnostics_oracle_test.go`.

## Element-access self references and generator evidence

`markPropertyAsReferenced` now receives the self-access parent the way pinned
Go computes it at each call site. Element access passes the apparent object
type's symbol, and property access passes the receiver's resolved symbol. The
containing-method search stops only at function-like declarations, so function
types and signatures inside a method no longer end it early. Native witnesses in

- local, static, `this`, `this`-typed alias and static self receivers in

## Interface inheritance checks

The interface declaration path now checks inherited-property identity before
relating the derived type to each base. It preserves Go's once-per-merged-symbol
guard, polymorphic `this` substitution, diagnostic chains and check order.
Conflicting inherited properties suppress base relations and index constraints;
member and duplicate-index checks still run. Merged generic declarations use the
existing type-parameter-list identity check.

The bounded comparison exposed two connected omissions, now fixed:
- A merged class/interface symbol resolves its class base followed by its
  interface bases. Previously, returning after the class base dropped the
  interface bases and produced false missing-abstract-member diagnostics.
- Heritage grammar rejects `implements`, repeated `extends`, empty lists and
  trailing commas. Only the first `extends` clause supplies base types; the
  later clause's identifiers are not resolved as additional bases.

Twenty-five native programs in `data/s08/p6/interface-inheritance` compare full
diagnostic payloads, including chains and related information, on initial and
repeated semantic requests. The requests, native provenance and reproduction
commands are retained with the fixtures.
