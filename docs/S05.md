# S05 scanner

Implemented on `codex/s05-scanner`, based on merged PRs #7 and #8.
The [implementation plan](S05-implementation-plan.md) was reviewed and
committed before implementation. The [protocol](S05-protocol.md) defines the
oracle, observations and exact scope of each metric.

## Contract and ownership

`tsr_scanner` scans borrowed bytes. BOM decoding belongs to `SourceText`, while
`Scanner::set_text` accepts already prepared raw bytes. Ordinary token text and
unchanged values borrow; cooked values share their owned byte storage. A getter
does not construct or classify a new JsString. Numeric caches are scanner-owned
and retain capacity across Reset; no lock belongs on the token path.

Scanner cursors and diagnostic offsets use `i64` for Go's supported 64-bit `int`
domain. S04's `isize` position APIs keep the same numeric width on these targets;
AST, TextRange and line-start storage remain `i32`. Producing a TokenRange narrows
through `TextRange::new`, matching Go, without clamping the scanner cursor.

An opaque, non-Clone Checkpoint retains state and is consumed by rewind or
commit in same-scanner LIFO order. SetText and Reset preserve outstanding
checkpoints. Rewind restores only state, so text/end, configuration, callbacks
and caches retain their current values. This supports current parser speculation
and JSDoc text replacement. Rust rejects unrestricted out-of-order/foreign state
restoration; the oracle does not claim Go slice-backing alias equivalence for
those excluded API operations.
Dropping a checkpoint does not commit it. If unwinding abandons a checkpoint,
discard that scanner; Reset preserves outstanding IDs and cannot repair that
abandoned nested scope. A focused test covers this recovery restriction.

Diagnostics preserve callback emission order, including regexp flag errors
before body errors and deferred references after parsing. Arguments retain raw
bytes and integer types. Release builds must execute Go debug assertions whose
expressions perform scanning; Rust debug_assert would omit their side effects.

Regexp recursion uses production stacker guards at disjunction and Unicode-set
expression entry points. Native tests must exercise growth from modest starting
stacks. This does not validate WebAssembly or Miri stack growth or complete the
future parser/checker/emit worker strategy.

## Dependency slices

`tsr_core` supplies open integer target/variant types and signed int32 text
ranges. `tsr_ast` adds pinned scanner flag and directive values alongside S03's
generated shapes. `tsr_jsnum` supplies numeric string conversion and scanner
bigint normalization; arithmetic and the remaining bigint value API are deferred.

The new direct capabilities are ryu-js 1.0.3 for ECMAScript number formatting,
num-bigint 0.5.1 with num-traits 0.2.19 for exact radix conversion, and stacker
0.1.25 for native stack growth. Their licenses/MSRVs and source APIs were reviewed;
Cargo.lock pins the complete dependency closure. They introduce fourteen
transitive/direct registry packages at initial resolution. Cargo-deny passes
advisories, duplicate-version, license and source checks.
`stacker` introduces a native `psm` build through `cc`; all four native CI targets
must compile it and execute the production growth/unwind tests in debug and
release. Minimum-version and dependency-policy checks alone cannot establish
that runtime coverage.

Pinned Go simple lowercase is reused separately from JavaScript casing.
EqualFold uses pinned SimpleFold cycles; dotted I versus ASCII i is a required
discriminator. Identifier ranges retain Unicode 15.1, while Go's casing/folding
uses Unicode 17. The table exporter records these authorities separately.

Verify tables with `python3 scripts/s05.py tables`; deliberately regenerate with
`python3 scripts/s05.py tables --write-manifest`. The implementation is
`scripts/s05_tables.py`, with provenance in `data/s05/tables-manifest.json` and
outputs in `data/s05/tables.json` and `crates/tsr_scanner/src/tables_generated.rs`.
The scanner producer runs the same drift check; S03's `cargo xtask gen` remains
separate. The plan records the exact Go Number.String formatting authority and
the rejected vendored-formatter alternative.

## Frozen evidence

The initial inventory was frozen before scanner behavior was ported:
33,323 requests, digest
`e56795ae01675f3c89873ef407e0baaa46540f2d6f6d9046ecbf25c18ed2f79a`.
Review added six bigint regressions and one partially closed deep Unicode set,
retaining every original request. A second review added an observed bounds panic and decoded UTF-16LE bigint
panic. The final inventory contains 33,332 requests, digest
`7045d660c44245b041a50c5530c7e0d871e61c8d2b7bb5a61dccae8b64e74fb7`.
It contains 12,854 physical source files / 12,427,814 bytes scanned in both trivia
modes (25,708 cases), plus explicit byte, rescan, regexp, helper and numeric
requests. Unicode blocks cover the full code-point range without counting each
point as a separate source file. Compiler test directives remain physical bytes;
this is a separate denominator from future E1 parser cases.

The parent validates each stream's own framing and then compares observations.
A different valid token count is a measured mismatch. Unknown or unapproved
panics fail the case; missing framing/actions, invalid types and stalled streams
fail capture. Frozen witnesses
prevent empty diagnostics from passing when both callbacks are omitted.

Only the scanner-specific E4 diagnostics and token-value criteria consume this
producer. The AST diagnostic ledger entry keeps its future E4 integration gate
alongside E1; passing scanner metrics cannot close it or full E4. A tracker
regression verifies that distinction.

## Validation record

The complete frozen comparison produced 4,982,432 observations per implementation
with zero mismatches. It includes 4,009 regexp cases, 904 rescan cases and
32,354 cases contributing diagnostic/value observations; those subsets overlap.
Native debug and release tests cover 20,000-level recursion from a 256 KiB
starting stack, callback unwinding, checkpoint lifetime restrictions, numeric
boundaries and adapter rejection paths. The locked workspace passes strict
Clippy and the declared Rust 1.96 minimum-version check.

The numeric dependency slice passed 23,042 additional development comparisons
against a clean export of the pin: 20,000 seeded float-bit patterns plus large
decimal/radix boundaries, whitespace and pseudo-bigint cases. No mismatch was
observed. These temporary development probes are separate from the frozen
scanner evidence count. A separate reviewer added 1,542 numeric boundary probes
and 30,000 malformed regexp probes; these also matched and are not included in
the frozen denominator.

One review-derived numeric example was wrong: `ParsePseudoBigInt("abc")` panics
because its second byte selects the radix branch; `"hello"` passes through.
The regression keeps both cases. Invalid bigint panics compare the exact input
bytes and operation-specific reason, retaining the raw Go quoted text and Rust
hex diagnostic; arbitrary panic pairs cannot pass.

Protocol regressions challenge duplicate keys, wrong panic payloads, source
decoding bookkeeping, differing valid token counts, missing EOF/actions,
diagnostic witness vacuity, absolute I/O deadlines, stderr flooding and producer
locking. CI publishes the full scanner failure records and adapter stderr along
with its evidence, including when a measured gate fails.

Function traceability is 144/158 (91.14%): regexp 34/34, scanner 104/112 and
utilities 6/12. The fourteen deferred functions are the ten node/ancestry helpers
listed in the plan, `GetScannerForSourceFile`, `ScanTokenAtPosition`,
`GetRangeOfTokenAtPosition` and the SourceFile-owned `GetECMALineStarts` accessor.
Partial source files retain `in-progress` ledger status. S05 does not complete
future AST diagnostics, full E4, full E3, S09 or performance measurements.
