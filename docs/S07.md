# S07 implementation and evidence

S07 adds file-owned binding and a source-selected program-loading slice. The
implementation is on [PR #11](https://github.com/iantocristian/ts-rust/pull/11),
stacked on [S06 PR #10](https://github.com/iantocristian/ts-rust/pull/10). The
[implementation plan](S07-implementation-plan.md) records the source contracts,
review dispositions and unchanged acceptance thresholds.

S07 remains open: the implementation passes its correctness comparisons, but
the measured parse/bind memory and CPU criteria fail.

The selected [S07-bis performance plan](S07-bis-performance-plan.md) tests
single-source exclusive binding before the compact AST/storage migration,
retaining published-file binding as the compatibility path. The
[exclusive-binding design record](S07-bis-exclusive-binding-alternative.md)
activates that bounded pilot and keeps a general published-file rewrite on hold;
[independent plan review](S07-bis-plan-review.md) records the amendments.

## Ownership and public boundaries

`tsr_binder::bind_source_file` publishes one immutable result per logical
SourceFile. Symbols, flow nodes, declaration backing and symbol tables belong
to that result. Graph IDs retain no owners. A normal bound view borrows the parsed file and binding;
escaping nodes and symbols explicitly retain their file or complete mapped
bundle. Binding stages sparse node changes privately and publishes them together.

The original initializer's panic unwinds to its caller and records terminal
failure. Contending callers see the same publication or terminal failure.
Same-thread reentry is detected before waiting; callbacks must not create a
cross-thread wait cycle. Recursive traversal uses production stack guards;
ordinary binary chains use explicit continuation frames. Separate depth probes
observe real stack growth and unwind through a grown stack.

The program host captures an immutable filesystem snapshot. File-cache reuse
requires identical source bytes, canonical identity, script kind and parse
options; weak cache entries do not keep retired snapshots live. Program metadata
belongs to the program, while shared parsed/bound files remain immutable.
Configuration diagnostics retain the configuration syntax they reference,
including inherited files.

The [binding operation record](S07-binding-operations.md) documents the explicit
boundary for binding shallow clones and transformed shared-child trees. This
Rust rejection is not counted as an upstream panic or as successful parity.

## What the comparisons establish

The primary binder denominator remains the parser's 12,829 rows and 22,343
expanded requests. Complete initial and repeated binding observations include
source state, node changes, symbol tables, declaration backing identities, flow
links and diagnostics. Constructed probes, helper observations, protocol
counterexamples and depth cases have independent gates; they add no primary rows.

The reviewed, frozen program subset has 10,728 effective variants. Its
selection reads pinned Go syntax/configuration observations, never Rust results.
The loader and config interpreter are compared separately: matching loaded files
does not establish config conversion or option diagnostics. Loaded declaration
libraries retain named future checker obligations, including generic operations
reached through those libraries. S07 does not claim checker parity or completion
of E2, E7 or E8.

Fresh, input-bound ledger captures match all primary binder requests and both
complete 13,094-file VS Code graph modes. The one-worker graph is byte-exact;
the eight-worker graph qualifies identity-derived names in 56 files (782 name
occurrences), with every referenced identity checked. Complete program config,
loader and option-verifier comparisons each pass all 10,728 frozen variants,
along with 25 helper tests and 11 source checks in the
[program capture](../status/evidence/cbaa73b694df7a0ef5e45bbf9436cc826c8ff5bb5b80fc22adb3a63e092ff699.json).
The
[implementation review record](S07-review.md) describes the independent findings
and their fixes.

Validation also passes 313 workspace tests in each of debug and release, eight
documentation tests, the exact 1.96.0 MSRV, formatting, Clippy and dependency
policy. The producer suite passes 287 Python tests and 60 tracker tests. All
seven S04, 24 S06 and 14 S07 ownership cases pass separately in debug, release,
strict-provenance Miri and ASan, with zero owner/allocation deltas. These scoped
ownership groups do not complete the entire E3 experiment.

## Measurements and remaining gates

The benchmark retains every parsed/bound file through its endpoint. The same
uninstrumented native executables provide full workload graph observations and
normal timing/RSS measurements. A separately identified allocation build measures
original layout requests. An eight-thread preflight checks allocation, zeroing,
reallocation, deallocation and final live-byte balance in debug and release.

The final capture contains 56 recorded samples: seven per runtime, worker mode
and normal/allocation configuration, after fixed warmups. The following values
are medians; GB is decimal. Every ratio is Rust / Go.

| Metric | Workers | Go | Rust | Ratio | Required |
| --- | ---: | ---: | ---: | ---: | ---: |
| Wall time | 1 | 2.938 s | 5.256 s | 1.789 | ≤ 1.0 |
| Wall time | 8 | 0.634 s | 1.224 s | 1.931 | ≤ 1.0 |
| Peak RSS | 1 | 3.156 GB | 4.565 GB | 1.447 | ≤ 0.7 |
| Peak RSS | 8 | 3.167 GB | 4.567 GB | 1.442 | ≤ 0.7 |
| Allocated bytes | 1 | 2.907 GB | 4.729 GB | 1.626 | ≤ 0.7 |
| Allocated bytes | 8 | 2.908 GB | 4.729 GB | 1.626 | ≤ 0.7 |

The [E5 capture](../status/evidence/30c6deb72aeba3cbead4d1a1d92f19aef0ef0feaf35d7add4623476885eb35f6.json)
uses the worse worker-mode ratio for each memory criterion. It covers only
parse/bind; E5's checker per-type footprint remains unmeasured. The
[E6 capture](../status/evidence/494380cb1f91f529c7c9cd9090d1fb465aa8448881275217e4b321bb984498af.json)
requires both time ratios and the fixed uncertainty gate. Its 95% bootstrap
intervals are [1.654, 1.883] at one worker and [1.858, 2.068] at eight. Relative
MAD is below 5% for all four timing groups, but both intervals are entirely
above 1.0, so `stable=false`. The fixed rule requires no additional batches for
this clear regression. No samples were discarded or selected for a better result.

Allocation instrumentation adds 0.2% to the one-worker Rust median and 53.2%
at eight workers in separate processes. Those informational overhead results
do not alter timing/RSS gates, which use the uninstrumented executable.

The measurement host is macOS arm64 with 18 available CPUs and 64 GiB RAM.
The producer requires at least eight available CPUs, records the host's memory
and platform, and rejects concurrent compiler/benchmark processes. Native CI on
the four supported targets runs correctness, ownership, stack-growth and
allocator checks. Hosted jobs do not manufacture performance results for an
underprovisioned runner.

## Reproducing evidence

Use the pinned Rust, Go and generator toolchains and initialize `upstream`.
Reusable oracle/toolchain/workload inputs live outside disposable Cargo output;
caller Cargo/Rustup and registry configuration remain available. A restricted
shell may need a writable caller-selected `GOCACHE`.

```sh
cargo xtask run binder
cargo xtask run e2
cargo xtask run program
cargo xtask run e3
cargo xtask run bindworkload
python3 scripts/s07_benchmark.py capture
cargo xtask run e5
cargo xtask run e6
cargo xtask status
cargo xtask check S07
```

`run e5` and `run e6` consume the same complete explicit measurement set. They
reject missing/stale graphs, changed binaries or sources, incomplete/reordered
samples, invalid numeric types and altered aggregates. A valid measured
regression is recorded as a failing metric. A missing prerequisite is a failed
producer. Neither outcome completes S07.

## Storage work required by the memory gate

The measured allocation result is about 1.626 times Go. At the one-worker Go
median, the 0.7 target permits 2.035 GB; Rust must remove about 2.693 GB, or 57%.
A separate development layout profile identified the following non-overlapping
payloads, which alone exceed that budget:

| Retained representation | Payload bytes, rounded |
| --- | ---: |
| 19,593,488 node records at 80 bytes | 1,567 MB |
| 2,459,867 symbol records at 112 bytes | 276 MB |
| 2,618,417 full binding records at 64 bytes | 168 MB |
| 21,324,288 allocated flow-reference slots at 8 bytes | 171 MB |
| Minimum subtotal | 2,181 MB |

This initial lower bound excludes boxed AST payloads, auxiliary/list backings,
flow graph nodes, map keys and spare capacity. The near-endpoint live-memory
peak did not establish low temporary traffic: the completed
[comparative memory diagnosis](S07-memory-profile.md) measures 923 MB of freed
or superseded Rust requests during the pipeline.

The new diagnosis contains eighteen matched diagnostic runs, paired retained
censuses, Go allocation-stack profiles and calibrated Rust source-region
counters. Approximately four-fifths of the compared extra retained allocation
appears during Rust binding. This locates allocation origin: Go embeds many
binding fields in parser-created nodes, while Rust adds side tables later.
The general binding map and flow slots account for at least 445 MB of retained
payload/capacity, including 177 MB beyond used payload; the full-map region
requests 633 MB during construction. They are the next bounded storage
experiment, with replacement metadata and lookup costs included.

These measurements do not show that the prototype will reach 0.7. The remaining
RSS domains and unclassified parser allocation regions are explicit in the
report. Checked public IDs, borrowed reads, complete retained ownership and Go
slice semantics remain required, followed by fresh full parity, ownership and
paired acceptance measurements.

## CPU work required before S07 closes

The [CPU diagnosis](S07-cpu-profile.md) now contains three fresh Rust and Go
profiles at each worker count, with eighteen additional controls and all frozen
work obligations checked. Separate diagnostic adapters preserve per-file
interleaving and retained roots; sampled CPU and elapsed worker timers remain
distinct. The report ranks AST access and traversal work ahead of changes to
final binding validation, and retains the raw profiles and analysis.

This diagnosis does not replace the acceptance capture or establish an
improvement. Benchmark each proposed change against the same frozen work and
preserve the full semantic/ownership gates. Meeting the present Go medians
requires roughly 44% less wall time at one worker and 48% less at eight, followed
by the same uncertainty qualification.
