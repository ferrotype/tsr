# S11 test-host transport

Status: implemented contract under owner review; ADR 0019 remains Proposed.

## Scope and authority

`ts_testhost --stdio` is a separate test binary and a reusable `serve` function.
It depends on the existing immutable VFS, serde and the standard library, with
no checker, program, project system or language service. S08 can evolve on its
own branch. This endpoint supplies transport seams; it does not execute
fourslash assertions or apply compiler options to a program.

The pinned `tsc/internal/api/callbackfs.go` is the authority for the five
filesystem operations. `internal/jsonrpc/baseproto.go` defines valid framing.
`internal/contentmapper/hostimpl.go` defines mapper method payloads; the endpoint
relays these payloads unchanged. `internal/fourslash/fourslash.go` injects FS,
parse cache, inferred options and a mapper spawner directly. The initialization
barrier, options updates and multiplexed plugin controls below are new test-host
contracts, not existing Go endpoint behavior. The parse-cache injection belongs
to Phase 5 and is not represented by a pretend cache here.

We choose an access-only overlay against the pin for oracle observations rather
than a fork of the fourslash harness. No upstream tracked source is modified.
The FS oracle calls actual callbackFS methods, records their callback requests,
and executes its injected base through vfstest. Process fixtures exercise Rust
through real framed stdin/stdout; pure state-machine tests alone cannot pass
`run.testhost.parity`. Mapper fixtures use the upstream test spawner over its
actual framed connection. New transport failure/control fixtures are labeled
contract observations, separately from Go comparisons.

## Implementation sequence and review

1. Inspect the Go injection seams and freeze filesystem and mapper observations.
   Record the fallback, encoding and lifecycle restrictions before implementing.
2. Implement bounded framing and duplicate-key rejection, then a single-threaded
   session router that keeps reading while callbacks are outstanding.
3. Add initialization/configuration barriers, immutable injected FS, and plugin
   proxy controls. Validate before mutation; callbacks never run under a lock.
4. Exercise fragmented/coalesced messages, out-of-order completion, cancellation,
   progress, remote errors, shutdown and disconnect over real child-process pipes.
5. Register a narrow `testhost` producer with an exact nonempty case manifest;
   retain raw transcripts, errors and Go observations. Add it to the active
   native producer jobs without claiming Phase 5 semantic coverage.
6. Independently review concrete protocol counterexamples, fix findings, run
   scoped Rust/Python checks, capture evidence and refresh tracker views. Submit
   the implemented design for the owner's ADR decision. S11-1 stays pending.

## Wire version 1

JSON-RPC 2.0 objects use `Content-Length: <UTF8 byte count>\r\n\r\n` framing.
Bodies are 1..8 MiB, headers at most 8 KiB. CRLF, one unsigned decimal length,
unique JSON object keys and finite JSON numbers are mandatory. Malformed frames
or envelopes terminate the connection with a diagnostic on stderr. stdout is
protocol-only. The parser accepts other well-formed headers but no JSON batches.
The endpoint advertises version 1; unknown versions are rejected.

JSON strings are strict Unicode/UTF8. This matches the expressible domain of the
Go JSON callback protocol; it is not an arbitrary-Go-byte-string transport. No
implicit replacement of invalid UTF8 is allowed. Byte-oriented compiler APIs
remain unchanged. Physical injected base files strip a UTF8 BOM via the VFS
loader; callback strings are already loaded and preserve it. A future arbitrary
byte extension requires a new explicit schema, not a lossy string conversion.

Client request IDs are strictly increasing positive safe integers (at most
2^53-1) for the life of a connection. Callback IDs are `callback:<n>` strings,
never reused. Unknown/duplicate callback responses are protocol errors. Responses
contain exactly one of `result` and `error`; application errors carry integer
`code`, string `message`, and optional `data`. Unknown request methods return
-32601; invalid parameters -32602; invalid lifecycle/busy -32002; callback or
base-FS failures -32001; cancellation -32800. Remote callback errors survive in
`error.data`. An error never means filesystem fallback or an empty mapper result.

There are at most 64 pending callbacks, including canceled callbacks waiting for
a late response, and at most 32 registered plugins. This bounds state when a peer
never completes canceled work. Plugin identity is a registered name scoped to
one connection. No shell command, disk fallback, package discovery or plugin
code is executed by the endpoint.

## Requests

`test/initialize` parameters:

```json
{"version":1,"caseSensitive":false,"base":{"/src/A.ts":"text"},
 "symlinks":{"/link.ts":"/src/A.ts"},"callbacks":["readFile","fileExists",
 "directoryExists","getAccessibleEntries","realpath"],"options":{},
 "plugins":[{"name":"mapper","options":{}}]}
```

All fields are required; unknown fields, duplicate callback/plugin names and
non-object options are rejected. Paths in the injected base/symlinks must be
slash-rooted and contain no NUL. Canonical/case-folded duplicates and
file/symlink ancestors of another injected entry are rejected before construction.
Query paths have the same slash-rooted/no-NUL domain; dot segments remain valid.
The server first requests `testhost/configuration` with `{options}`.
Only a callback result `{"ready":true}` commits initialization. It responds
with `{version:1,caseSensitive,options,plugins}` and emits
`testhost/initialized` with `{version:1}`. Requests before this barrier fail.
Failed/canceled initialization can be retried with a fresh request ID after its
callback response has been consumed. Cancellation alone does not acknowledge
that the host has finished configuration.

`test/setOptions` takes `{options: <object>}` and uses the same configuration
callback/barrier. It replaces options only after success and returns `{options}`.
It requires no pending operations and blocks new FS/plugin requests until the
configuration callback completes, including when the request was canceled.
A canceled callback must still return a result or error; until then the client
can observe state or shut down, but cannot overtake configuration with new work.
State observation sees the old options until that commit. This establishes
transport ordering only; Phase 5 must connect the configuration callback to
actual project updates.
`test/state` takes `{}` and reports current initialization settings plus plugin
states for fixture observation.

`test/fs` takes `{operation:<one of the five names>,path:<string>}`. Enabled
operations issue a reverse request using that operation's exact Go method name
and path string as params. Disabled operations directly use the injected base.
A null callback result delegates exclusively to that base. `readFile` results
are `{content:string|null}` (missing versus successful empty retained); exists
operations return booleans, listings `{files:[string],directories:[string]}`,
and realpath a string. Callback listings retain order and duplicates, as Go does.
Wire listings omit the Go-only optional symlink-knowledge map on both runtimes;
this is a deliberate projection, not a claim that unknown equals known-empty.
Malformed callback result types are errors; unlike the Go internal adapter,
invalid boolean payloads do not quietly become false.

`test/plugin` takes `{name,method,params}`. Registered plugin options are sent to
`testhost/plugin` together with those three fields. Allowed methods are `spawn`,
`initialize`, `openProject`, `transform`, `closeProject`, `dispose`. Params must
be an object. The client owns the spawner/process and all project handles.
`spawn` succeeds only with null and moves registered -> spawned; `initialize`
requires spawned and moves to ready; open/transform/close require ready;
`dispose` requires spawned/ready and returns to registered only on null success.
Only one request per plugin may be outstanding. Mapper request/result fields,
mapping tuples and diagnostic payloads are passed unchanged, without performing
source mapping or language-service assertions. Failed callbacks keep the prior
state. A canceled plugin call retires that name for the rest of the session;
`testhost/retirePlugin` tells the host to dispose all its resources, including
late spawn results. Session disconnect requires the host to dispose every plugin.
No claim is made that canceled remote side effects can be rolled back.

`test/shutdown` takes `{}`. It cancels live operations, forwards cancellation for
pending callbacks, requests retirement of plugin resources, acknowledges shutdown
and closes the transport. No later response can revive the closed session.

## Notifications, progress and cancellation

Client `$/cancelRequest` params `{id:<client request ID>}` sends one -32800 final
response, a `$/cancelRequest` notification for the associated callback ID, and
one `testhost/progress` end notification. Unknown/already finished IDs are no-ops.
A late callback response is consumed without completing canceled work again.
Capacity remains charged until that response or disconnect.

Each reverse request emits `testhost/progress` `{id,callback,phase:"begin"}`
before the request and `phase:"end"` before its final client response. Client
`test/callbackProgress` `{callback:<callback ID>,value:<JSON>}` forwards
`testhost/progress` `{id,callback,phase:"report",value}` only for live callbacks.
This is callback transport progress, not LSP work-done progress. Cancellation,
progress and unrelated responses are processed while any callback waits.

## Bounds, verification and review record

Outbound request and response sizes are checked before registering callbacks or
committing configuration/plugin state. Options admission reserves the longest
plugin-state spelling, so a later dispose cannot make `test/state` exceed the
frame limit. A combined plugin payload that exceeds
the frame limit returns -32602. An oversized wrapped callback result/error
returns a bounded -32001 response; it cannot turn into an empty success.
Large-frame test transcripts retain SHA256, byte count and identity; ordinary
frames are retained in full. Large payloads are reproducibly defined in fixture
source, so evidence does not duplicate tens of megabytes of padding.

The initial independent review identified canonical path collisions/ancestor
conflicts, operations admitted during an options update, and frame expansion
following state mutation. These were corrected before the acceptance capture
and added to the named transport inventory. No checker or parser tests are
re-run for this independent transport implementation.

Run `cargo test -p ts_testhost`, `python3 -m unittest discover -s scripts/tests
-p test_s11.py`, then `cargo xtask run testhost`. The producer needs the initialized
pinned upstream submodule and pinned Go (GOTOOLCHAIN=local), and preserves caller
cache/mirror settings. Its temporary exports are removed; reports go under
`target/s11-reports/` and into the tracker's immutable capture stderr. The same
producer and debug/release contracts run on the two currently active native CI
targets; the owner's temporary macOS Intel/Ubuntu ARM pause remains in effect.
ADR 0019 must remain Proposed until the owner reviews this concrete result.

### Review after merging S10

Merged S10 at `9770a57` without rewriting the published S11 history. The review
found two transport defects, reproduced before their fixes:

* A canceled configuration callback released its barrier before the host's
  response. New FS/plugin requests could overtake an options update, and a new
  initialization could overtake a canceled initialization. Both barriers now
  remain until the outstanding response is consumed.
* An options update sized `test/state` with the plugin's current spelling.
  With a near-limit payload, changing `ready` to `registered` on disposal made
  the state unreadable. Admission now reserves all plugins' longest spelling.

Three named subprocess regressions cover those counterexamples. The inventory
is now 75 cases: 30 pinned-Go filesystem cases, five actual Go mapper sequences,
and 40 transport/control contracts. The original S11 capture is retained as
historical evidence; the combined source tree requires a new capture. No S10
benchmark or compiler corpus is rerun for this independent transport review.
