# S11 test-host transport

Status: wire version 2; architecture accepted by the owner in ADR 0019 on
2026-09-19. S11 completion still requires current evidence and its S06 prerequisite.

## Scope and authority

`tsr_testhost --stdio`, `serve` and `Session` implement a transport prototype.
There is no compiler, project system, mapper host or language service running
inside it. Pinned `internal/api/callbackfs.go` supplies filesystem truth;
`internal/jsonrpc/baseproto.go` supplies framing; `contentmapper.Spawner` supplies
the raw stream boundary. The Go fourslash harness remains the executable
specification, driven through a carried transport patch in Phase 5.

S11 proves input continues while asynchronous callbacks wait and while streams
lack credit. It does not prove the synchronous filesystem-to-reverse-request
bridge with blocked worker threads. That bridge, parse-cache injection, real
project options, the production mapper host, LSP integration and semantic
fourslash assertions are explicit Phase 5 work. A client must drain stdout;
the synchronous framing writer can block on a peer that stops reading.

## Implementation and review sequence

1. Replace increasing IDs with typed LSP IDs and test reuse across cancellation.
2. Replace the configuration callback with private staged state and an internal
   completion hook, including delayed, failed and canceled outcomes.
3. Replace the six-method mapper proxy with opaque stream transport. Bound
   chunks, credits and tombstones; preserve stdout/stderr and exit distinctions.
4. Record actual Go test-spawner bytes before protocol decoding. Replay both
   directions with different fragmentation and compare complete byte streams.
5. Run focused Rust debug/release/MSRV and lint checks, script validation,
   subprocess contracts and the testhost producer. Refresh committed views.
   Do not rerun unrelated compiler corpora or benchmarks for this transport.

## Wire version 2

JSON-RPC objects use `Content-Length: <UTF8 byte count>\r\n\r\n`.
Bodies are 1..8 MiB, headers at most 8 KiB, nesting at most 64. Reject duplicate
lengths, duplicate object keys, invalid JSON numbers, trailing input, lone
surrogates and invalid UTF8. Well-formed extra headers are accepted; JSON batches
are not. Malformed input terminates the connection with a stderr diagnostic;
stdout contains only protocol frames. Version 1 initialization is rejected.

Client request IDs are strings or signed 32-bit integers (zero and negatives
included). Numeric `1`, string `"1"` and empty string `""` are distinct. IDs may
be reused after the final response, but not while in flight. Server callback IDs
are never-reused `callback:<n>` strings in the opposite direction's namespace.
A client request may itself use `"callback:1"`. Dispatch uses message direction
and shape, never a reserved client prefix. Canceled callback reservations remain
until their late reply but cannot complete or report progress on a reused ID.

Bounds include the actual serialized ID. A request whose ID leaves no room for
even a minimal error cannot be admitted and closes the connection before work.
Otherwise oversized replies produce bounded errors. Responses contain exactly
one result or error. Codes: unknown method -32601, invalid params -32602,
not-initialized/busy -32002, host failure -32001, cancellation -32800.
Unknown/duplicate callback responses are protocol errors. Remote errors retain
code/message/data under `error.data` when the resulting envelope fits.

JSON strings are strict Unicode. Arbitrary-byte source files therefore cannot
cross the filesystem JSON interface: this is a known gap against the repository
text contract, not permission to replace bytes. The binary mapper tunnel has no
such limitation. Opaque options, progress and error data preserve raw numeric
syntax, including oversized integers, decimal precision and negative zero.

There are at most 64 pending callbacks including canceled reservations, and 32
registered plugins. There are at most 64 stream identities per session, including closed tombstones.
A new spawn is refused before contacting the client once that budget is exhausted.
Closed identities cannot be reused; a new session resets the budget.
The endpoint executes no shell commands, disk reads or plugin code.

## Server-owned initialization and options

`test/initialize` requires:

```json
{"version":2,"caseSensitive":false,"base":{"/src/A.ts":"text"},
 "symlinks":{"/link.ts":"/src/A.ts"},"callbacks":["readFile"],"options":{},
 "plugins":[{"name":"mapper","options":{}}]}
```

Unknown fields, non-object options, duplicate registrations or callback names,
and invalid injected paths are rejected before application. Paths are slash-rooted
and NUL-free; canonical/case-folded collisions and file/symlink ancestors of other
entries are rejected. Dot segments in query paths remain valid.

Initialization stages the configuration privately. `Session::pending_options`
exposes a borrowed options payload, a process-unique opaque completion token and
the cancellation-requested flag. `Session::complete_options(token, outcome)` is
an internal hook: success means applied; failure guarantees no applied change.
Stale, cross-session and post-shutdown tokens cannot publish. The executable's
S11 stub completes immediately; unit contracts deliberately hold the hook open.
There is no `testhost/configuration` request or client acknowledgment.

Success returns `{version:2,caseSensitive,options,plugins}` and then sends
`testhost/initialized {version:2}`. Failed initialization leaves no published
configuration and can be retried. `test/setOptions {options:<object>}` uses the
same hook and replaces options on success, returning `{options}`. It requires
an idle callback queue. While either update is pending, new FS, spawn and stream
writes are refused; existing stream input, reads and close remain serviceable.
`test/state {}` observes old options until commit and reports plugin states.

Cancellation marks the internal update but leaves its request and ordering
barrier active until completion. If the hook reports no applied change, return
-32800; if application won the race, return success and publish the new state.
A late cancellation after the final response is a no-op. Phase 5 must coordinate
its actual side effects with this commit boundary; the S11 stub does not prove
project-system atomicity. Shutdown retires pending tokens; no later completion
may apply to that session.

All locally known state/response sizes are checked before exposing the hook.
Options admission reserves the longest plugin-state spelling. A future state
query with an unusually long ID can receive a bounded size error without
changing state. The real LSP `workspace/configuration` exchange remains separate
and will participate in Phase 5 initialization, as it does in Go's `InitComplete`.

## Filesystem callbacks

`test/fs {operation,path}` supports readFile, fileExists, directoryExists,
getAccessibleEntries and realpath. Enabled operations reverse-call the client
with the exact Go method name and path string; disabled operations use the
injected immutable base. A null callback result delegates to that base only.

readFile results are `{content:string|null}`. Missing `content`, including `{}`,
means missing and suppresses fallback; empty string means an existing empty file.
Exists operations return booleans; listings `{files:[string],directories:[string]}`;
realpath returns a string. Callback listing order and duplicates are preserved.
The wire projects out Go's optional symlink-knowledge map on both sides. Wrong
boolean/result shapes return an error instead of Go's internal false coercion.
Symlink cycles return an error in this prototype; cycle equivalence with Go is
not claimed. writeFile is outside the five-operation scope.

Physical base files pass through the existing VFS BOM handling; callback content
is already loaded text and retains its BOM. No malformed source bytes are repaired.

## Plugin stream tunnel

`test/openPlugin {name}` is the S11 driver's entry into the spawner seam. It
issues `testhost/spawnPlugin {name,options}`. The client resolves the registered
name to its configured spawner, owns all process resources, and replies
`{stream:<new string of 1..256 UTF8 bytes>}`. A successful spawn publishes that
identity; a spawn error guarantees no live child and permits retry. A malformed
success or canceled spawn retires the name and sends `testhost/retirePlugin {name}`.
The client must dispose resources including children returned after cancellation.

States are registered → opening → open; ordinary close/exit returns the name to
registered and permits another spawn with a new stream identity. Cancellation or
an ambiguous spawn result moves to retired for the rest of this session. Late
notifications for an old stream cannot change the replacement child's state. There is no mapper-method dispatch and no limit of
one outstanding mapper request. Mapper frames can be fragmented, coalesced or
interleaved with traffic from other streams. Per-stream bytes retain their order.

Chunks contain 1..32768 decoded bytes, encoded as canonical padded standard
base64. Each input channel has a 65536-byte window. On spawn the endpoint sends
`testhost/streamCredit {stream,channel:"stdout"|"stderr",bytes:65536}` twice.
The client sends `test/streamData {stream,channel,data}` only within that credit.
The endpoint buffers those bytes and replenishes credit only after consumption.
Receive overrun, invalid base64 or data after EOF is a protocol error. Client
stderr is never mixed into mapper stdout or the endpoint's diagnostic stderr.

For server-to-plugin stdin, the client grants `test/streamCredit {stream,bytes}`.
Outstanding credit cannot exceed 65536. The S11 driver uses
`test/streamWrite {stream,data}`, which emits `testhost/streamData {stream,data}`
and returns null. Insufficient credit gives a busy error without consuming bytes;
the caller retries after credit. Admission does not wait for a process write.
A client returns credit only when its own bounded write queue has room.

The fixture driver consumes output through
`test/streamRead {stream,channel,maxBytes}` (1..32768). The result is `{data,eof}`:
null data with false EOF means would-block; base64 data contains the consumed
bytes; empty data with true EOF means exhausted. Reads may return data and true
EOF together. No bytes are consumed if the response cannot fit. These driver
operations exercise the shared stream state; the Phase 5 mapper host will consume
this seam through its adapter. The synchronous worker adapter is not implemented.

Client `test/streamEnd {stream,channel}` marks EOF after all data for that channel.
`test/streamExit {stream,code:<i32|null>}` follows both channel EOFs; null explicitly
means unavailable. Exit must be reported once and preserves unread output.
`test/streamStatus {stream}` reports `{closed,exit}` with exit states `running`,
`unavailable`, or `exited` with `code`. After exit, stdin writes are refused.

Either peer may abort the whole stream. Driver `test/closeStream {stream}` emits
`testhost/streamClose {stream}` and returns null; client `test/streamClose {stream}`
is a notification. Full close discards buffered bytes and tears down the process,
as Go's `ReadWriteCloser.Close` requires. Close is idempotent. Valid late chunks
on a locally closed stream are discarded, never delivered to a replacement;
a final exit report remains accepted. Disconnect requires client cleanup of all
registered resources. No unavailable exit code is synthesized as zero.

## Progress, cancellation and shutdown

Each filesystem/spawn reverse request emits `testhost/progress` with
`{id,callback,phase:"begin"}`, then the request. Completion emits `phase:"end"`
before the final response. `test/callbackProgress {callback,value}` forwards a
report only while that callback is live. Wrapping overflow cancels only the
owning operation with -32001; unrelated requests survive. Spawn overflow also
retires the plugin name. Internal options updates do not create callbacks.

Client `$/cancelRequest {id}` cancels a live reverse operation: notify cancellation
for its callback ID, end progress, send one -32800 response. Retain the canceled
callback reservation until its late response or disconnect. Internal options
cancellation follows its separate completion contract above. Unknown/completed
IDs are no-ops. These are LSP cancellation semantics; `testhost/progress` remains
separate from LSP `$/progress` on the future shared connection.

`test/shutdown {}` cancels callbacks and internal updates, closes streams, replies
null and closes the transport. No later completion revives that session. EOF
with unresolved callbacks/internal updates is diagnosed; the client always owns
resource cleanup on disconnect.

## Evidence and maintenance

The native filesystem oracle calls pinned callbackFS over injected vfstest.
The mapper oracle wraps the actual Go test-spawner connection, recording bytes
successfully written/read before protocol decoding. Each of the five sequences
retains its decoded observations as a coverage check as well as both raw streams.
The producer verifies every framed request and response against the frozen
sequence, replays bytes with different chunk boundaries, and compares exact
concatenated bytes in each direction. It never reserializes a decoded response
and labels that native byte equality.

New lifecycle, fragmentation, binary, backpressure, malformed input and concurrent
traffic tests are transport contracts, separately labeled from Go observations.
The delayed internal-hook tests execute the real Session API and are included as
internal contract rows. They do not count as subprocess or blocked-worker proof.
Large padding transcripts retain hashes and lengths; ordinary frames and actual
mapper byte streams are retained. No success is inferred from missing cases.

Run `cargo test -p tsr_testhost` (debug and release), scoped clippy with warnings
denied, Rust 1.96 check, the `test_s11.py` script tests, then `cargo xtask run
testhost` and tracker validation/views. The producer uses the pinned local Go
with access-only temporary overlays, preserves caches and removes exports.
`base64` 0.22.1 supplies the standard codec and strict padding validation instead
of implementing a new codec; it is confined to this transport dependency.

Version-1 evidence covered the removed method/configuration proxy. It remains in
history. The revised capture covers only version 2 and does not refresh unrelated
S06/S09/S10 evidence or certify the Phase 5 semantic integration.
