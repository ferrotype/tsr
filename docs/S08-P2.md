## Implementation sequence

1. Correct the deferred P0 review contracts: classify the primitive relation
   shortcuts accurately, enforce reviewed unresolved-site identities, distinguish
   harness failures from native outcomes, and make lease teardown and contention
   tests prove their stated behavior. Preserve original observations and record
   metadata changes separately from new native captures.
2. Retain the immutable program behind the checker owner. Implement the compiler
   host from existing loader data, propagating filesystem and AST failures. Read
   source symbols through borrowed views; clone declarations and member/export
   tables into checker-owned stores before merges. No mutation of published
   binding results and no owner clones or locks per node lookup.
3. Port initialization, globals and the first declaration/name/type query paths
   from the pinned Go checker. Reuse the binder's resolver with checker hooks.
   Every unfinished branch remains a named unsupported operation. Extend these
   paths through intrinsic, literal and anonymous object types rather than
   introducing a separate fixture evaluator.
4. Build type syntax through the checker node builder and print it through
   `tsr_printer`. Connect structured diagnostics and baseline rendering for the
   same named programs, including an erroneous program. Keep display, semantic
   errors and unsupported operations distinct.
5. Compare original Go and Rust observations for these real programs, including
   checker-local merges under single-checker, repeated, separate-checker and
   concurrent execution. Verify shared source symbols stay unchanged and
   retained results keep their program alive. Expand only from the resulting
   named missing-operation list.

## Implementation and review details

`ProgramCheckerHost` borrows existing program files, resolutions, metadata,
options and paths, with explicit failures for unported host operations. The
checker owns the host. Source reads borrow that retained owner; operations take
one exclusive lease and do not clone owners or acquire locks per node.

Symbol merging clones into checker-owned storage. A source declaration slice is
borrowed with its capacity capped; the first nonempty append imports only that
slice into private backing. Parent/member/export traversal preserves the source
identity graph. A raw symbol handle deliberately preserves the exact input
identity, as Go's symbol-taking APIs do; name/location lookup supplies this
checker's merged symbol.

The first queries use the existing binder name resolver with checker lookup and
side effects. Type display constructs real syntax in a temporary AST owner and
runs `tsr_printer`. Source checking supports the named declaration/literal/plain
object/assignment path; unsupported grammar, relations and options are explicit
failures. A failed file check stays failed, and an unsupported member resolution
does not mark its members resolved.

The independent reviews focused on query/cache boundaries and shared ownership.
Two valid findings were corrected before delivery: JSDoc type references need
special primitive-name mapping, and an interface nested in a generic declaration
has outer type parameters. Both now return a named unsupported operation before
publishing a misleading ordinary type. Regression tests cover both, including
lazy JSDoc nodes in a distinct retained arena. The ownership review found no
shared-source mutation or exposed partial merge state.

The P0 review cleanup is included in a separate commit. Its original requests
and native observations were reused, not recaptured. P2 updates only the frozen
metadata fingerprints affected by the host contract and the added script; the
native dependency closure and supplemental observation archives are unchanged.

The scaffold's blanket dead-code allowances are removed. Unused helpers were
removed or limited to tests/census. P1 record fields still needed by P3/P4 retain
individual reasons naming their pending consumers; no record layout was changed
to silence a warning. This is explicit remaining implementation debt.

## P2 review corrections

The follow-up review was checked against pin
`1f70213d4922b434345f639b441681e470c7cfc1` and small native counterexamples.
The following changes are included:

- A readonly assignment reports TS2588 and skips the assignment relation, while
  still checking its right side. It no longer adds TS2322 against a const literal.
- Missing const initialization short-circuits the subsequent name grammar check,
  without skipping the remaining semantic work. The executable fixture uses
  `const let: number;`; unannotated implicit typing remains unsupported.
- Symbol queries pass `isUse=true` through the shared name resolver. The existing
  checker reference links receive its callbacks; unused-local checking is still
  explicitly unsupported.
- A type-reference identifier query preserves the actual pinned `errorType`
  result (displayed as `any`). Querying the complete `Foo` reference or its
  resolved symbol remains distinct. The review's claim that the native identifier
  query returns the declared type was disproved by a native capture.
- The native and Rust display calls now both have no enclosing declaration.
  Default display uses `AllowUniqueESSymbolType |
  UseAliasDefinedOutsideCurrentScope`; alias expansion uses `InTypeAlias`.
  Enclosing-scope qualification, annotation reuse and unique-symbol support remain
  later display work. The suggested hex counterexample prints `{ a: 16; }` in
  both implementations, including the original contextual native call.
- Normal expression checking now caches successful results in the existing node
  links. Declaration checking and non-quick initializer inference share those
  results. Quick literal inference retains Go's uncached path. A failed enclosing
  widening operation does not turn successful initializer work into a failed cache
  entry: a focused test proves retries allocate no additional types or symbols
  while still returning the unsupported widening result. Failed initializer
  checking does not publish a result. P3/P4 must add Go's flow-stack/cache
  save-clear-restore protocol when flow-dependent expressions become supported.

Two proposed changes were rejected: pinned Go checks interfaces synchronously
and has the same transient-symbol parent guard as Rust. No diagnostic queue or
merge-parent divergence was introduced. The lazy/imported-owner fallback remains
an O(files) worst-case lookup, separate from the indexed core path; its cost has
not been measured and remains a follow-up.

Follow-up validation: all 29 queries across six programs and all four merge modes
match, with no unsupported operations or mismatches; all 12 semantic integration
tests and nine Python protocol tests pass. The readonly test also preserves a
right-side BigInt grammar diagnostic on ES2019. Focused package Clippy across all
targets/features passes with warnings denied. P0's existing captures were reused;
only the broader source-inventory fingerprint of `scripts/s08_p2.py` changes.

The original archive is retained. `data/s08/p2/review-fixes.tar.xz` contains the
