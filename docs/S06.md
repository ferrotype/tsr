# S06 implementation record

S06 adds the native TypeScript parser, JSDoc parser/reparser, mutable AST runtime
and protocol-8 encoder/decoder on top of S03's generated schema and S05's scanner.
The source authority is the canonical Go pin
`1f70213d4922b434345f639b441681e470c7cfc1`; Go semantic data and sorting behavior
also use the shared Go 1.27.1 toolchain pin.

## Public boundaries

`tsr_parser::parse_source_file` accepts already-loaded `SourceText`, an open
`ScriptKind`, and `SourceFileParseOptions`. It returns an exclusive `ParsedFile`.
The caller may borrow its `AstView` or retain exclusive construction for S07
binding. `publish_unbound` consumes it into shared storage for parser tools; that
operation deliberately makes no claim that binding ran. Invalid ownership edges
are checked again at completion and publication.

`on_parser_worker` runs a whole operation/batch on the reserved native stack;
nested calls execute inline. Recursive parser guards are the primary protection.
Small-stack tests verify actual segment growth in optimized builds, including
JSDoc and namespace reparsing. Lazy JSDoc enters the worker before taking its
publication lock, and the borrowed transaction stays on that thread.

`tsr_encoder::encode_source_file` uses the source-owned position map and lazy
node-index table through an explicit `ParserJsDocProvider`. The decoder preserves
Go's protocol widths, nil results, lossy decoding, source contract panics and
error text. Valid encoding is not assumed to imply successful decoding or an
identical round trip.

## Ownership and observable behavior

The AST header is the arena's actual record. Lists, text fragments, source
metadata, diagnostics and lazy graphs share its retention root. Ordinary core
reads borrow storage without a lock or owner reference-count operation. Mutating
an existing source-metadata element during construction also changes a clone's
shared backing; replacing its slice header does not. No growable metadata slice
capacity API is exposed. Empty parser metadata and empty JSDoc results allocate
no backing by default.

Source text and parse options cannot be replaced after construction. A logical
source owns its own derived caches even when several sources share one storage
owner and cloned children. Cached references are checked against that source's
canonical file/bundle retention graph, excluding unrelated importing owners.
An initializer's source panic completes its sync.Once state with nil; a Rust
ownership error leaves initialization retryable. Same-thread reentry is
explicitly diagnosed.

Checked arena identity and Go's lazy comparison ID are separate types/operations.
The node-index sorter reproduces Go's comparison order because it affects which
IDs are assigned first and which duplicate index binary search returns. The
sorter carries the upstream BSD license and independent comparison traces.

Generic AST accessors distinguish payload interfaces from kind dispatch. Factory
updates preserve upstream identity tests and hook order; clone operations reset
only the fields Go resets. Generated wire properties do not replace the visitor
member inventory: FullSignature is the relevant counterexample.

ancillary assets remain recorded, and no supplemental test dilutes the primary
denominator. The corpus manifest records loader stages, directives, VFS metadata,
options, exclusions and both source/request hashes.

The full capture requires exact successful encoder bytes and independently
classified outcomes, along with runtime, decoder and depth results. Two frozen
keyword-split diagnostic fixtures retain Go's observed nondeterministic choices

Unknown panics, unexpected returned-error stages, missing output and ordinary
request timeouts invalidate or fail capture.

A separate subprocess watchdog observes both production decoders still running

returned-decoder parity rows.

Required local checks also include `cargo xtask run gen`, `scanner`, `e4`,

## Later phases

Binding, checking, whole-program/project-reference loading, mapper execution,
printer output and compiler diagnostic baselines remain later-sprint work.
SyntheticExpression construction/updates/cloning stay deferred until its checker
Type link has real ownership; codec rejection is implemented. The direct parser
corpus is not E2 compiler conformance, and S06's encoder criteria do not complete
E4's S08 literal-type and printer integration.

## Independent implementation review follow-up

A fresh review after the implementation was pushed found two concrete defects.
The generated decoder grouped JavaScript type aliases/imports with their ordinary
TypeScript payload shapes and called the default constructor, changing kinds
345/346 into 266/273. The authoritative emitter now dispatches schema aliases to
their specific constructors. Two ordinary JavaScript parse/encode/decode traces
and four raw shared-payload cases prove the distinction; a high-bit position
probe confirms both runtimes retain signed-32 storage narrowing.

The published AST API also exposed generic arena writers through `storage()` and
retained-node `owner()`, and accepted unchecked generic storage through
`from_storage()`. A caller could inject a foreign child after AST publication
validation. Those public routes are removed. `RetainedNode` keeps its generic
handle private and exposes checked AST access and explicit file retention.
Three compile-fail witnesses close the escape paths, and the existing runtime
foreign-edge/cache test rejects the corresponding AST transaction. The frozen
24-case ownership inventory remains unchanged.
