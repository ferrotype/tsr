# F5b scanner operation coverage audit

The scanner ledger already had the S05 paired action producer, but its operation-level links stopped at the spelling helpers. The existing-evidence audit adds 133 previously unlinked operation identities: 128 scanner/regexp identities from 65 explicit S05 call-path observations, four S04 position helpers, and the `GetTextOfNode` path of an existing S07 helper fixture. A subsequent bounded implementation adds the missing `GetTextOfJSDocComment` port and 12 direct paired requests covering that operation and eight remaining source-line/AST convenience helpers. The combined tranche accounts for 142 exact identities; it does not credit unobserved branches.

## Evidence contract

`witness/s05-scanner-operation-actions` in `data/phase1/cases.json` is the machine-readable map. Its `operation_actions` keys contain an exact request ID, zero-based action index and operation; `operation_paths` explains which observable output exposes the path. Native execution is `scripts/s05_oracle/protocol.go`, Rust execution is `crates/tsr_scanner/examples/s05.rs`, and `scripts/s05_protocol.py` compares ordered token/scalar/diagnostic records. Setup setters are linked to the later result affected by their value. Token getters are called by both snapshot routines and their individual fields are compared.

This maps operation execution to an observable contract; it does not claim every branch is covered. A helper merely appearing in a source file or beneath a possible caller does not qualify. For example, escaped JSDoc identifier `\u0041` is action18 of `rescan/jsdoc/tokens`; actions19–23 are EOF and are not claimed as escape parsing. The raw-file variant link names one concrete closing-tag source rather than the scanner corpus generally.

The existing `scanner`, `e4` and `binder` producer freshness checks still apply. Adding these links does not make a stale run current. No full producer, benchmark or broad test suite was rerun for this audit. One bounded invocation of the existing Rust S05 binary confirmed the JSDoc action18 token position; that check locates the action, not replacement parity evidence. All claimed request/action identities and operation IDs were checked against the committed manifests, and the four E4 IDs were regenerated from the committed request generator.

## Position and AST helper links

`witness/s04-scanner-position-actions` names four exact astral probes: `utf8/astral/00027` (`ComputeLineOfPosition`), `utf8/astral/00106` (`ComputePositionOfLineAndByteOffset`), `utf16/astral/00124` (`ComputePositionOfLineAndUTF16Character`) and `utf16/astral/00029` (`GetECMALineAndUTF16CharacterOfPosition`). Both E4 adapters call those same operations and compare numeric/tuple results. The source-file convenience wrappers are not inferred from these lower-level calls.

`witness/s07-scanner-declaration-text-path` adds only `GetTextOfNode`. The `name/real` observation calls `DeclarationNameToString` on a parented identifier, which unconditionally calls the helper in both implementations; the compared bytes skip leading trivia and retain the raw trailing byte.

## Direct source-line and AST helper tranche

`data/phase1/requests/syntax-scanner-ast.json` supplies 13 requests to the syntax driver and `tools/phase1/syntax/scanner_ast_probe_test.go`. Each adapter validates the requested call against its exact operation identity, constructs its own source file and typed nodes from the request, and executes the production helper. The native adapter calls the pinned scanner API directly. No expected output is supplied to either adapter.

| Requests | Exact operations and observed contract |
| --- | --- |
| `comment-nil`, `comment-empty`, `comment-source-links-unicode-space`, `comment-nonspace-format-characters`, `comment-malformed-final-byte`, `comment-only-unicode-space` | `GetTextOfJSDocComment`: concatenate stored text and raw source spellings of the three link kinds; ignore other kinds; preserve leading spaces, malformed bytes, U+200B and U+FEFF; trim all 25 Unicode White_Space codepoints at the end; nil and empty return empty bytes. |
| `comment-nil-element` | `GetTextOfJSDocComment`: a list containing a null node raises the actual nil-pointer panic. Only this named request catches the exact native panic message; normal returns fail the request, and unexpected panics propagate. |
| `source-line-wrappers`, `source-empty-line-cache` | `GetECMALineStarts`, `GetECMALineOfPosition`, `GetECMALineAndByteOffsetOfPosition`, `GetECMAPositionOfLineAndByteOffset`, `GetECMAPositionOfLineAndUTF16Character`: compare the owner-cached line starts twice, stable cache identity, byte offsets versus UTF-16 positions over astral text, CRLF, U+2028 and trailing LF; empty input remains one line. |
| `token-positions`, `token-position-jsdoc-leading-star` | `GetTokenPosOfNode`: empty/missing nodes, JSX text, trivia, included versus excluded JSDoc, JSDoc text/link spelling and leading-star trivia. |
| `scan-token-at-position` | `ScanTokenAtPosition`: the exact token kind after trivia and at several source offsets, including EOF. |
| `identifier-keyword-kind` | `IdentifierToKeywordKind`: keyword names and its distinct Unknown fallback for ordinary, escaped-looking, malformed and empty names. |

Go's `GetECMALineStarts` is only a forwarder to `SourceFile.ECMALineMap()`. Its Rust equivalent in these requests is the production `SourceFileState::ecma_line_map()` getter, rather than a new redundant scanner wrapper. The other four line helpers call their separately annotated scanner-position APIs; their coverage is not inferred from E4's lower-level operations.

The JSDoc helper now lives in `crates/tsr_scanner/src/binder_helpers.rs`. Its trim step uses strict last-rune decoding and Unicode White_Space, as the pin does; JavaScript trivia predicates would incorrectly strip U+200B or U+FEFF. The narrow unit `binder_helpers::tests::jsdoc_comment_text_keeps_nonspace_bytes_and_rejects_foreign_lists` verifies malformed-byte retention, exclusions and an owner mismatch, and is registered in `data/s07/helper-tests.json` so the existing helper producer executes it. That unit and `cargo check -p phase1_syntax --locked` passed. The focused driver regression `scanner_ast::tests::nil_element_observation_requires_the_actual_native_panic` checks successful text trimming, the actual null-element panic, rejection of a normal return, rejection of another request identity, and propagation of unexpected or ordinary-request panics. The final syntax capture/record remains the freshness authority; these cases stay `not_run` until that capture is authenticated.
