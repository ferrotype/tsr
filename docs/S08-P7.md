## Checkerbench

### Executables

- Rust: `crates/tsr_compiler/examples/p7_checkerbench.rs` over the shared
  diagnostic executor and the P5 walker, built three ways from
  `crates/tsr_compiler/Cargo.toml` features. The normal timing binary has no
  feature: no query JSON, phase clocks or allocation counting. `s08-phase-timer`
  compiles `tools/s08/p7/instrument.rs`, nested exclusive clocks for
  initialization, checking and display. `s08-allocation` compiles the S07 `cap`
  wrapper around mimalloc (requested and live bytes at the allocator boundary;
  `cap` counts no allocation calls, reported as unavailable) and enables the
  checker's `storage-pilot` census.
- The executor (`tools/s08/p4/executor.rs`) takes a `Hooks` object. The interval
  starts after loading, parsing, binding and the loader-graph observation; every
  diagnostic JSON conversion inside it is bracketed by `pause`/`resume`; checker
  construction (`CheckerOwner::for_program` and the operation) is the `init`
  phase; the checkpoint runs after the complete schedule with the checker and
  every result live. The P5 corpus observer (`tools/s08/p5/corpus.rs`) pauses
  around the error-baseline rendering (baseline decoration) and passes the
  walker's retained `GetTypeAtLocation` results as roots.
- The walker (`tools/s08/p5/baseline`) has a count-only recording mode: the
  checkerbench child counts operations instead of building query JSON inside the
  interval, and wraps `TypeToTypeNode`+printer, `SymbolToStringEx` and the public
  `TypeToString` display in the display clock (child display time is subtracted
  from the enclosing check clock).
- Go: the E2 baseline overlay (`scripts/s08_baselines.overlay_sources`) plus
  `tools/s08/oracle/checkerbench/`: a clock in package `core`, the checker
  construction hook in `checkerpool.createCheckers`, a compile hook that replaces
  the harness's pre/post double compile with one program, `BindSourceFiles`
  before the interval and the pre-emit diagnostic sequence inside it (the frozen
  E2 comparison established that Rust's single non-emitting pass produces the
  same diagnostics), count-only query recording, display clocks around the same
  three display sites, retained roots and the `S08Census` structural census at
  the checkpoint (below).
  `S08_MODE` selects normal, phase or alloc. `TS_TEST_PROGRAM_SINGLE_THREADED=1`
  keeps one checker.
- Both children hash the same produced bytes after the interval (types and
  symbols baselines, error baseline, public type strings, the sorted
  deduplicated diagnostics as code:file:pos:end) and report the executed action
  counts per variant. The driver requires identical action counts per variant
  and identical output digests for every variant across all runtimes, modes and
  samples, including warmups. A mismatch invalidates the capture.

### Driver

`scripts/s08_checkerbench.py`: `build` (three release Rust binaries with exact
Cargo artifact selection, one Go test binary compiled with the overlay),
`capture` (the acceptance requests from the current E2 corpus capture checked
against `data/s08/baseline-requests.json`; per executable kind one warmup Go
then Rust, then seven alternating fresh-process samples in the frozen order),

the producer; `report.json` is only a derived view. Older protocol captures
need recapture. A completed capture cannot be overwritten by `capture`.

## Per-type footprint

**Review status (2026-09-16): incomplete accounting; do not use the ratios below
for a gate decision.** The six original fixtures and a ten-variant allocation
smoke completed, but targeted counterexamples exposed omitted mapper edges,
incorrect shared-backing accounting and unmeasured storage. The corrected
mapper walk reports its opaque function captures as unavailable. The historical
0.924 subset ratio below is therefore not a validated footprint result. See
the census review record at the end of this document.

Both allocation executables run a structural census at checkpoint 2 with the
walker's retained types as roots. The aggregate mean over all variants is
`sum(type_storage_bytes) / sum(types.reachable)` per runtime, Rust over Go.
Unreachable occupied records stay in the numerator. A failed census or any
unavailable family or root inventory on any measured variant makes the
footprint metric unavailable; a family is never reported as zero when its
extent is unknown.

### Required ownership rules (implementation gaps recorded below)

- Every allocation is charged once, by physical identity (data pointer) and
  full extent (capacity, not length; hash-table control bytes and directories
  included; allocator size-class slack excluded on both sides). Shared
  backings, subslices and re-exported lists therefore add nothing on their
  second visit.
- Bound inputs are separated, never charged: program file texts (by backing
  address), binder symbol tables and non-transient symbols. Checker strings
  that alias a file text, and payload fields that point at binder tables or
  symbols, are counted under `bound_inputs` (`references`,
  `binder_table_references`, `binder_symbol_references` on the Go side).
- Type-owned member backing has precedence over the other checker buckets:
  a member table owned by a reached type is charged to that type's family and
  removed from `symbol_tables`, whichever path reached it first. Alias records
  are storage, not extra logical types. Map entries count as records only for
  the checker's own cache maps; a map nested in a record is that record's
  storage.
- The denominator is the set of unique `Type` identities reachable from the
  live checker's semantic fields, caches, link stores and the retained roots.

### Rust adapter

`Operation::census` (`storage-pilot` feature) walks every type payload table,
cache, link store and side table of `CheckerState`. This revision adds the
program file texts as registered bound-input backings, measures the synthetic
checker AST structurally (`AstBuilder::structural_bytes`: node payload pages,
auxiliary lists and backings, links, text pool, edge pages, imports and the
storage owner), measures the display node-builder's cached ASTs
(`display_ast`) and the printer side tables (`display_emit`) instead of
declaring them unavailable, replaces `capacity()` with hashbrown's exact
`allocation_size()` for every measured map (std capacity misleads after
deletions), and attributes type-owned member tables through
`SymbolTables::table_structural_bytes`.

### Go adapter

`S08Census` (`tools/s08/oracle/families/census_v2.go`) replaces the P1
`S08FamiliesCensus` at the checkerbench checkpoint. In allocation runs the
extent of every reached allocation comes from the runtime allocation
observer described under "Follow-up corrections" below; the structural model
described here charges what the observer cannot see, is the fallback when no
observer is present (the fixture programs' second census) and is the
cross-check the fixture run compares the observed extents against. The
census reflects over every
field of the live `Checker`: fields are classified by an explicit table
(unlisted `*Type` fields are roots, function fields are skipped, anything else
unclassified marks `unclassified_field:<name>` unavailable); `LinkStore`,
`PagedLinkStore`, the node and symbol link stores, the node factory arenas and
the diagnostics collection are walked record by record; every `*Type` reached
from a field, link record, payload or root is a semantic root; all twenty
concrete `TypeData` kinds are charged once with the embedded `Type` header
never counted twice, and an unknown payload kind marks
`type_payload:<type>` unavailable. Map bytes come from the runtime's swiss-map
layout (`internal/runtime/maps`: the 48-byte header, the directory, each
unique table with its group array of `lengthMask+1` groups of `GroupSize`;
a small map is one group), self-checked against the `abi.MapType` key and
element layout, with unsupported layouts marked `map_layout:<type>`
unavailable. `core.Arena` chunk capacities are replayed with the real element
type through `reflect.AppendSlice`, which reproduces `slices.Grow`'s
size-class rounding including the malloc header of pointerful chunks. Unit
tests (`census_v2_test.go`) check the map layout against the runtime for small
maps and after deletions, the arena replay and current-chunk inference against
a live arena, that every `Checker` field is classified, and that shared
allocations are charged once.
The P1 `arenaChunks` model in `bridge.go` records a chunk only when the
capacity changes and therefore undercounts chunks once an arena reaches its
256-record plateau; the P1 record stands as recorded and the new census does
not use it. The output adds a per-`Checker`-field byte breakdown (`fields`)
for diagnosis.

## Relater

### Reference prototype

`tools/s08/relater-prototype` keeps its P1 construction and mutation API (strong
`Rc` cells owned by the graph, `Weak` edges, `OnceCell` lazy structure, consumed
resolvers, explicit `Released`/`ResolutionFailed`/`UndeclaredMember` failures,
`#![forbid(unsafe_code)]`) and now carries intrinsics, literals (fresh and
regular forms), unions, intersections and object types with properties, index
signatures and non-generic call/construct signatures. The algorithm ports the
pinned `relater.go` paths for those kinds: `isTypeRelatedTo`,
`isSimpleTypeRelatedTo`, `isRelatedToEx` (with the common-property and weak-type
checks), the union/intersection family, `recursiveTypeRelatedTo` with recursion
flags, expanding flags, deeply-nested identities, the complexity budget and the
maybe stack, `structuredTypeRelatedTo` with the intersection extra passes,
properties (unmatched, optionality, readonly, identity), signatures
(`compareSignaturesRelated` for non-generic signatures with callback
bivariance, identity) and index signatures (applicable infos, member inference,
identity). Paths that would need generic instantiation, inference,
conditional, mapped, template-literal or tuple machinery fail explicitly with
`Error::Unsupported` and are reported, never approximated. Every
`checkTypeRelatedTo` outcome is recorded (the Go observer's `ternary_calls`),
one diagnostic chain is emitted per failed reported relation.

A [`Description`] is the prototype's input: a plain snapshot of types (flags,
object flags, symbol and alias identities, literal values, members with their
optional/readonly/class-member bits, index infos, signature shapes, union and
intersection constituents). `Graph::construct` allocates every cell, links
union constituents after all cells exist and gives every object a lazy resolver
that materializes members, index infos and signatures on first use (counted as
`lazy_records`).

### Comparison child

`crates/tsr_compiler/examples/p7_relater.rs` (`relation-probe`, optionally
`s08-allocation`) runs one ordered pass of the 21 frozen fixtures, five mode
groups each, on a 256 MiB worker stack. Per group: a fresh production checker,
the A/B declared-type lookup (setup), then the four actions (relation interval).
`--implementation id` relates through the production relation probe.
`--implementation reference` additionally translates the reachable production
types into a description (new read-only `Operation` handles: `index_infos`,
`signatures_of_type`, `signature_shape`, `literal_shape`, `is_readonly_symbol`,
`alias_symbol`), constructs the prototype graph inside setup and relates in the
prototype. Setup and relation intervals, their requested bytes and live bytes
before/after each group are recorded separately.

`scripts/s08_relater.py`: `parity` compares both implementations with the frozen
Go observations (`data/s08/supplemental-observations.json.xz`, request digest
checked against the archived inventory). The ID side compares results,
ternary calls, before/after counters and caches, and structured diagnostics.
The reference strict comparison now checks diagnostic payloads, not just counts,
and explicitly fails the lazy-work contract because setup pre-resolves the
production graph. Its old projection (results, ternary calls, cache deltas,
diagnostic counts and lookup cache state) is retained only as
`reference_behavior_agreement`, separate from `parity_reference`.

### Sampling stability on the development host (2026-09-18)

Every full checkerbench capture so far has recorded `stable: false`, and the
report's host-load flag has fired on every one. That is a property of the host,
not of either implementation, and the contract asks for it to be disclosed
rather than suppressed, so the threshold stays at max/min > 1.10.

What the samples actually show, on the capture recorded at 92fdaa9:

- Byte counts are exact. All seven samples per runtime returned identical
  `requested_bytes`, `retained_bytes` and census totals, so the allocation,
  retention and footprint ratios carry no sampling uncertainty at all.
- Only wall clock moves, and it moves on both sides: Go max/min 1.258, Rust
  1.143 in normal mode. Go, the faster runtime with the shorter interval, is the
  noisier of the two, which is what host interference looks like rather than a
  property of the port.
- `host_busy` is set because the one-minute load average never approaches the
  2.0 threshold on a machine that is simultaneously running the capture's own
  toolchain and builds.

`run.checkerbench.stable` gates nothing. The three E2 checkerbench criteria are
presence gates on positive finite measurements, and E2 passes with the flag
false. The only `stable` criterion in `status/experiments.toml` is
`run.e6.stable`, a different producer. Raising the threshold to clear the flag
would relabel the same samples, invalidate the capture's authenticated
`method_sha256` and cost a two-hour recapture, so it was considered and
rejected. The quiet-host capture remains the way to retire this, and the
ratios that matter for the footprint and allocation gates are unaffected by it.

## PR review corrections

The review fixes change measurement/validation code, not checker algorithms.
No full benchmark or full-corpus capture was run for this revision. Focused
replay tests cover altered raw artifacts, missing/reordered samples, forged
counts, changed executables, cross-runtime output mismatch, census failure or
unavailable families, equal-count/wrong-payload diagnostics, and equal group
inventories with incomparable lazy work. Signed retained deltas are preserved
instead of clamped to zero. Historical smoke figures above remain explicitly
unverified under the new protocol.

Validation of the correction: 15 focused Python replay tests, seven Rust native
walker/configuration/diagnostic tests, P7 example clippy with warnings denied,
Go overlay compilation and the nested-clock unit test, fmt and ledger
validation. One frozen acceptance variant matched on outputs and action counts
in Rust normal and Go normal/phase/allocation adapters; each raw summary was
independently reconstructed. No benchmark acceptance evidence was produced.

### Follow-up corrections

Allocation extents now come from a diagnostic runtime overlay on pinned Go
1.27.1. It records original allocation requests, including the fourteen
compiler-specialized entry points and `mallocgc`, and snapshots heap identities
before checker construction. The SDK files are unchanged. Normal and phase
binaries use the stock runtime; only the allocation binary contains this
observer. Its SDK-source hashes and executable digest are recorded and verified.

The observer stores addresses and type metadata as integer values in a bounded
static buffer, never as semantic roots. Snapshot/index construction is outside
the measured interval. Overflow, missing provenance, unsupported layout or a
truncated graph traversal makes the census unavailable. The buffer holds
2^23 records (335 MB of BSS, resident only as far as it is written); the first
full capture needed up to 1.93 million interval records plus a pre-interval
snapshot below 0.67 million and overflowed the former 2^20 on 9 of 9,369
variants. Every census reports the observer's log use (`observer`: recorded,
snapshot, capacity, overflow), the checkerbench report summarizes the maximum
use and the unavailable family names per runtime, and the fixture check

### Init: the globals merge, and the harness hashing before the interval (2026-09-17)

Init was a flat 233 µs per checker over Go on the recorded run. A sampling
profile of the 4,000 smallest variants put 87% of it in `mergeGlobalSymbol`:
every lib symbol's name copied into an owning string and a temporary
`HashMap` before being interned into the checker's globals table, the
target symbol's member and export tables cloned the same way, the merged
name copied once more for the insert, the name hashed twice, and the globals
table rehashed ten times while it grew from empty to its 2,205 entries. Go
does the same merge with map clones and pointer-sized entries.

Four changes, none to what is merged: `SymbolTables::clone_own` copies a
checker-owned table's hash table wholesale (names and slots are already
encoded for the store) and `clone_foreign` interns a binder-owned table once
into a table sized for it; `merge_symbol_table` walks one byte buffer of the
source's names instead of an owning string per entry; `merge_global_symbol`
hashes the name once (`tsr_ast::name_hash`) and reads it in place for the
insert; and `initialize_program` reserves the globals table and the name pool
for the largest global file's locals (dom's 2,022 of the 2,205 final
entries), which is the capacity the table grows to anyway.

The child also spent 57% of its process time outside the interval in
SHA-256: the program observation digests every file text per variant,
including the lib files, and the checkerbench row never uses it. A
`Hooks::wants_graph` flag, default on, lets the checkerbench child skip the
observation. Beyond the process time, that hashing streamed megabytes
through the caches right before each interval started.

### Node reads: one validation per read (2026-09-17)

What `self.ast(node)?.node(node)?` did, at about 1,900 sites in the checker:
select the file view (directory lookup, a 6-word view built from the shared
owner), `for_node_owner` (four arena comparisons and a full slot validation
with the page arithmetic and its bounds checks), then `node` (arena compare,
overlay check, and the same slot validation again before the header read).
Go's equivalent is one pointer load. The typed read that follows still pays a
shape dispatch and a second paged lookup for the payload row; that is the
next layer, not this one.

`SharedBoundFile::node(id)` reads the header directly when the file's binding
wrote its core in place (`reads_core_directly`), otherwise it takes the
routed view. `ProgramContext::node` reaches it through the last-hit
directory, and `CheckerState::node` adds the factory arena in front.
The 1,932 same-id `ast(n)?.node(n)?` sites became `node(n)?` mechanically
(a regex with a back-reference; the two ids were identical at every site).
`node_text` (171 sites) and `source_file_read` (37) take a directory-only
view (`ProgramContext::view_of`) since both validate the id themselves; that
step measured neutral, those sites are cold.

Flattening the growth pages was tried and reverted. `Arena` gained a sealed
contiguous form filled at `StorageBuilder::publish`, so a slot read became
one bounds check; interleaved A/B pairs showed lib-check, deep-flow, median
and first-300 variants inside noise and the 4,000 smallest variants about 4%
slower. The page arithmetic was not on the critical path, and a neutral
change with more code does not land.

### Inline-aware profile: string churn in member resolution (2026-09-17)

`sample` attributes inlined helpers to their callers, which is why the
check-phase self time looked flat. A `samply` recording of a release build
with line tables, symbolicated through `atos -i`, gives self time by the
innermost inlined function. On the lib-check variants the top items were
small (2.7% at most) but two families summed: the node and symbol access
plumbing at about a quarter of the phase, and string handling at 7–9%:
`SymbolRef::name_to_owned` (4.9%) and `JsString::from_bytes` (6.9%, with the
UTF-8 classification each construction runs). Their callers were
`get_named_members`, `resolve_object_type_members` and the relater's
`properties_related_except`: an owning string per member, per property, per
comparison, where Go reads its map keys and `symbol.Name` in place.

Changes, none to what is computed:

- `get_named_members` reads the members table once, filters reserved names
  on the bytes in place, hoists the container's declaration ranges out of
  the per-member loop (they were re-read per member) and sorts symbol ids;
  no string is built.
- `resolve_object_type_members` puts instantiated members straight into a
  checker table from one byte buffer of names, copies the own members with
  `clone_symbol_table`, reserves the inherited table per base and inserts
  inherited names read in place through a field-level symbol read
  (`split_symbol`), instead of an owned map with a string per entry copied
  into the arena afterwards. `resolve_anonymous_type_members` likewise.
- The relater's property loops copy a name into a 64-byte stack buffer
  (`NameBuf`) for the span of the mutating lookup instead of allocating a
  string, and compare excluded names by bytes.
- `FastHasher::write` takes whole words with `as_chunks` and folds the tail
  by shifts; the profile showed a per-chunk conversion check and a library
  copy for the sub-word tail. Measured neutral; kept as the simpler form.

### View selection without validation, and the module-export walk (2026-09-17)

A fresh inline-aware profile at the previous commit put the routed
`CheckerState::ast` at 10% of the check phase inclusive. Its remaining
callers take the view only to hand it to a helper that reads the node
itself: the name resolver's host (3.2%), `is_static_private_identifier_property`
(1.9%), `conditional_flow_type`, `source_list`, `eager_jsdoc_for_node`,
`type_of_parameter`. Every read through the view validates its own id, so a
directory hit in `ProgramContext::ast` now returns the file view without
`for_node_owner`; other arenas keep the routed, validating path, and
`view_of` folded back into `ast`. Interleaved A/B: lib-check variants
1,187–1,236 → 1,046–1,060 ms, the deep flow variant 327–337 → 266–272 ms,
ordinary variants flat.

The same profiles put the hash function itself at 30% of init's self time
on the smallest variants and 21% of display's at the median: the lib merge
interns every member name of every multiply-declared interface, and the
module-export walk hashed each export several times. Two hasher variants
were tried and not kept: a folded 128-bit multiply per 16 bytes for every
write regressed the check-heavy variants by 7–15% (the id-keyed lookups
check is made of pay the multiply's latency), and folding byte strings only
was a wash, since most names are shorter than 16 bytes. A probe of the name
pool's final size (about 2,480 names on ordinary variants against a reserve
of 2,022; 6,166 on lib-check variants) showed the pool does not grow on
ordinary variants; reserving merge targets for their source was neutral and
not kept.

The module-export walk (`getExportsOfModuleWorker`) built, per module: a set
of every export name as owning strings, a standard map with an owning string
per export (SipHash), the arena copy of that map, and a second pass over the
name set. It now clones the exports table into a checker table directly
(Go's `maps.Clone`), extends it from star exports through one byte buffer
per source table, and records the visited tables instead of their names,
reading them only when a type-only star recorded anything. Under a host
load of 16 the A/B could not be sized; the median and first-300 subsets ran
faster in both pairs and no subset ran slower. The full normal run at that
load measured 16.75 s, not comparable with the 14.82 s of the previous
section at a load of about 6; the interleaved subsets are the evidence.
