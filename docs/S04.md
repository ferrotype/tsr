# S04: text and ownership contract leaves

The [synthesis plan](S04-synthesis-plan.md) records the choices drawn from the four
earlier S04 implementations. This implementation targets the accepted
[text](design/text.md) and [ownership](design/ownership.md) notes against upstream
pin `1f70213d4922b434345f639b441681e470c7cfc1`.

## Text

`tsr_jsstring` separates immutable byte strings, BOM decoding, the WTF-8 codec,
casing, literal escaping, and the three position-conversion paths into modules.
Byte slices share storage and classify their own contents. Invalid UTF-8 remains
representable; callers must explicitly request a valid string view.

The decoder is chosen per upstream operation. JavaScript casing preserves lone
surrogate sentinels; Go-style rune truncation may split them. JavaScript casing
tables come from the upstream generated data, while `LowerFirstChar` uses the
simple-lower table generated from pinned Go 1.27.1. Rust's changing Unicode tables
do not determine that helper's output.

API, LSP and scanner offsets retain their signed arithmetic, bounds and rounding
rules. UTF-16 offset 1 within `😀` maps to byte 1 through the API, 0 through LSP,
and 4 through the scanner utility. ECMAScript and LSP line maps keep their distinct
line-break sets. A converted byte offset need not be a Rust string boundary.

## Ownership

`tsr_arena` uses nonzero packed ids with a process-global, never-reused arena
counter. Production construction cannot inject duplicate arena identities.
Mutable file builders are consumed at publication. Core reads borrow immutable
storage; branded local slots support repeated access after validation. Explicit
retained references keep escaped nodes and their file or entire mapped bundle
alive. Bundle member links are ids, so cyclic links do not create ownership cycles.

Lazy storage uses stable `OnceLock` pages. One standard-library `RwLock` guards
cache lookup, miss recheck, slot reservation and publication. Graph construction
is staged privately; failure burns provisional ids without publishing partial
nodes. Initializer panics are resumed after releasing the guard so a later valid
request can retry. Returned token errors do not poison the lock. Cache entries
retain ids only, and escaped references retain the required owner. Same-thread
initializer reentry to the same file's lazy storage panics before locking;
ordinary contention still waits. Initializers must not wait for another thread
to access that storage.

The source text and its API position map belong to the file. A `OnceLock` builds
the map on first access, avoiding a second scan at file publication. Checker identity
and lease primitives establish identity/exclusion boundaries only; semantic
checker storage, callback reentry and atomic server response commitment remain
later integration work.

## Evidence contract

E4 exports the production internals and module files from the upstream pin to
temporary storage, adds wrappers
for private helpers, builds the Go oracle, and compares it with the Rust adapter.
The canonical submodule is not modified. The producer rejects malformed JSON,
duplicate keys, missing/extra/reordered probes and mismatched JSON types. Scenario
ids and probe coverage are frozen separately, preventing a smaller probe set
inside an existing scenario from silently passing. Every panic payload is retained.
All 10,664 scanner contract panics compare their messages exactly; 6,326 runtime
bounds panics compare a narrowly recognized bounds class. Assertions, overflow
and unrecognized panics cannot pass by matching another panic.

The 13,064 slice probes compare bounds, bytes and Go's valid UTF-8 string view.
Upstream has no three-way UTF-8/WTF-8/raw classifier, so its oracle does not emit
a modeled validity tag. Rust tests check classification and reclassification
invariants separately; the differential count does not represent upstream
validation of those tags.

E3 executes the same seven required scenario functions in debug, release, Miri
and AddressSanitizer. The native report cannot claim instrumentation completion;
the producer records it only after the required tests actually finish in each
mode. The native example catches each scenario's panic, reports that criterion
as failed with its diagnostic, and continues through the remaining scenarios.
If any scenario fails, aggregate counters and instrumentation metrics are omitted.
Miri and ASan failures have independent false metrics and captured diagnostics.
Additional regressions cover failed transactions, type-level brands, lazy
reentry, concurrent map initialization and retention. Missing tools, skipped
scenarios and malformed reports cannot satisfy the gate.

Counters measure live owners and explicitly tracked storage units: owner objects,
nonempty core/symbol slabs and lazy pages. They exclude payload allocations and
cache/directory bookkeeping. Each scenario checks nonzero activity and final-drop
return to baseline. These are disposal checks, not heap-byte or RSS measurements.

Miri uses strict provenance with the production standard-library locks. ASan
rebuilds the standard library with address instrumentation. macOS does not support
LeakSanitizer, so leak detection there rests separately on Miri and final-drop
counter checks. The CI workflow runs the producers and enforces their metrics on
all four configured macOS/Linux targets; local evidence establishes only the
target recorded in its execution artifacts. Each producer can capture evidence
after an unrelated install or producer failure. S09-5 additionally requires the
full E3 experiment, so instrumenting only S04's scenarios cannot complete it.

## Reproduce

Use Go 1.27.1 and the repository's pinned Rust toolchain. Install instrumentation
tools separately:

```sh
git submodule update --init upstream
rustup toolchain install nightly-2026-09-05 \
  --profile minimal --component miri --component rust-src --no-self-update
cargo test --workspace --locked
cargo xtask run selftest
cargo xtask run workspace
cargo xtask run oracle
cargo xtask run fmt
cargo xtask run clippy
cargo xtask run deny
cargo xtask run e4
cargo xtask run e3
cargo xtask status
cargo xtask validate
cargo xtask check S04
cargo xtask status --check-committed
```

`data/s04/toolchains.toml`, the corpus and frozen coverage manifests are hashed
producer inputs. CI and the casing-table generator read this toolchain manifest;
its MSRV must match the workspace declaration. `GOTOOLCHAIN=local` prevents Go
from silently switching the compiler used for the oracle.

The producers preserve caller Cargo and Rustup homes, including registry mirrors
and offline configuration. `S04_RUSTUP_HOME` optionally selects a separate
instrumentation installation. Reusable Miri sysroots and the Go build cache live
under the platform's user cache directory, or `S04_CACHE_HOME`; an explicit
`GOCACHE` is preserved. CI caches them and the pinned nightly outside `target/`.
The Go oracle uses `-trimpath` so temporary export paths do not invalidate its
compilation cache. Missing toolchains and uncached dependencies still need to be
provisioned before an offline run.

`status/evidence/e3.latest` and `e4.latest` select the captured
executions; [current status](../STATUS.md) reevaluates them against the current
source. Editing a selected input invalidates the corresponding old measurement.

## Remaining scope

S04 does not complete E3 or E4. Real programs/snapshots, checker and builder
retention, registry retirement and server commitment, scanner/parser/encoder
integration, literal types and whole-printer output still require their later
sprints. Compiler throughput, retained heap bytes and full WebAssembly/embedding
acceptance also remain unmeasured here.
