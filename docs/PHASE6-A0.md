# Phase 6 A0 — protocol generation and the acceptance path

A0 is the first checkpoint of the JS API server port (the plan is
`docs/PHASE6-plan.md` on the `phase6-plan` branch). It delivers the generated
protocol, the handwritten codecs and their pinned fixtures, the `tsrust --api`
skeleton, the `jsapi` parity suite with its CI job, and the first full run
whose failing set `status/parity/jsapi.json` records with cause labels.

## What landed

- **Emitter.** `cargo xtask gen api [--check]` reads `data/s03/schema/api.json`
  (142 methods, 128 types) and writes `crates/tsr_api/src/proto/generated.rs`:
  the `Method` enum with wire ids and Go constant names, the `Params` enum
  decoded by method, the scalar newtypes, one struct per DTO in the export's
  order with `tsr_json` codecs honoring `jsonName`, `omitempty`, `omitzero`
  and non-nil slices, and references to the handwritten types of
  `proto/codecs.rs` (`DocumentIdentifier`, `RawBinary`, the compiler-option,
  project-reference and type-acquisition values, the ordered string-list map,
  the package.json value, the numeric enums of `tsr_core`). The lint job runs
  `gen api --check`.
- **Codec fixtures.** The 36 observations of `data/s03/api-wire-fixtures.json`
  are `tsr_api` tests (`proto/tests.rs`): marshal and unmarshal byte for byte,
  and the error class for the failing fixtures.
- **`tsrust --api`.** `crates/tsrust/src/api.rs` parses the pin's six flags as
  Go's `flag` package does (`api/flags.rs`), accepts one stdio connection in
  the protocol `--async` selects (msgpack tuples or JSON-RPC) and answers
  `ping` and `echo`; every other method fails with `not implemented: <method>`
  for a known method and `unknown method: <method>` otherwise.
- **The `jsapi` suite.** `tools/phase6/jsapi/` (`reporter.mjs`, `runner.py`,
  `inventory.py`, `README.md`) and `scripts/phase6_parity.py` run the
  untouched pinned client tests (`upstream/packages/typescript/test`, 12
  files) under Node 24.20.0 from the pin's `volta` entry, native binary first
  and Rust second, under the L7 comparison rules. `parity.py` gains the suite
  (`run`, `check`, `accept`) and `.github/workflows/ci.yml` a `jsapi` job.
  The pinned `api.test.ts` files import `api.bench.ts`, which needs
  `tinybench`, so the client's dependencies are installed with
  `npm ci --ignore-scripts` in `upstream/` (`node_modules` is ignored by the
  pin; `runner.py prepare` checks for it).
- **`docs/PHASE6-tests.md`**, generated by `inventory.py` from the native
  run's events and the pinned Go tests of `internal/api`: the client cases by
  file and the 56 Go tests with a route each.

## The first full run

Host: macOS arm64, 18 CPUs, Node v24.20.0, pin `1f70213d`.

| Measure | Value |
| --- | ---: |
| Test files (variants) | 12 |
| Client cases, native run | 706 |
| Native skips / native failures | 0 / 0 |
| Cases passing against the A0 skeleton | 86 |
| Cases failing against the A0 skeleton | 620 |
| Files failing as a whole | 1 (`test/async/api.test.ts`, worker deadline) |
| Suite time, native and Rust, without the deadline | about 30 s |
| Release build of the binaries before the run (warm target) | 2 min 53 s |

The plan expected 669 client cases from a static count; the native run
executes 706 because parameterized cases register at run time. The native
figure is the denominator from here on.

The 86 passing cases never reach the server: `encoder` (26), `spanMap` (15),
`sync/ast` (36), `scanner`, `version`, `wtf8` (4), and the cases of the two
`api.test.ts` files and `api-generators` that only construct clients (5).

Every failing case carries a mechanical cause label computed by
`runner.classify` from the client's error text, so later checkpoints show
their progress by label without anyone wording a reason:

| Label | Cases |
| --- | ---: |
| `server: not implemented: initialize` | 603 |
| `server: not implemented: batchRequests` | 8 |
| `cancelled by parent` (`astnav`, both clients) | 8 |
| `server: unknown method: getServerTiming` | 1 |
| `deadline: 600 s` (the `test/async/api.test.ts` file) | 1 |

No approval is recorded; closure requires the owner's approvals only.

### The async worker deadline

Against the A0 skeleton the `test/async/api.test.ts` worker finishes its 274
tests in under two seconds but never exits: one test's promise stays pending
(Node reports `Promise resolution is still pending but the event loop has
already resolved` and counts one cancelled test), so the runner's per-file
deadline ends the file. No server process survives the tests, so this is
the client waiting on the skeleton, not a leaked `tsrust`.

`--test-force-exit` was tried and rejected: it ends the worker before its
event stream to the parent is drained, and the native run of
`test/sync/api.test.ts` lost 37 of its 267 cases and `test/sync/ast.test.ts`
16 of 100 to truncation. The deadline stays the guard; A1, which answers
`initialize`, re-examines the pending promise.

## Checks against the plan's exit criteria

- Emitter, codecs and fixtures green: `cargo test -p tsr_api` (7 tests) and
  `cargo xtask gen api --check` pass; a one-byte edit of the generated file
  fails the check.
- The suite runs end to end for native and Rust (`parity.py run jsapi`),
  `check` passes against the accepted expectation file, and the harness tests
  (`scripts/tests/test_phase6_jsapi.py`, 6 tests) cover the reporter fixture,
  the parent mapping, the file-failure and the cause labels.
- The native run passes everything: 706 of 706.

## Local recipe

```sh
python3 tools/phase6/jsapi/runner.py prepare --binaries target/phase6/binaries   # native-lsp and rust-lsp
python3 scripts/parity.py run jsapi --output "$SCRATCH/jsapi"                      # about 30 s plus deadlines
python3 scripts/parity.py check jsapi --results "$SCRATCH/jsapi"
python3 tools/phase6/jsapi/inventory.py --results "$SCRATCH/jsapi/local/0/native.ndjson" --markdown docs/PHASE6-tests.md
```

`upstream/` needs `npm ci --ignore-scripts` once per lockfile change.
