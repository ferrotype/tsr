## Scope and correctness

The implementation includes checker-owned types, symbols and signatures;
declaration merging; construction, relations and narrowing for the frozen
slice; the loaded-library operations those queries require; the printer and
node builder used by type display; and declaration diagnostics required by the
native test runner. It does not establish full TypeScript emit, language-service
or server coverage. The [implementation plan](S08-implementation-plan.md),
[P6 record](S08-P6.md) and [E2 protocol](S08-E2.md) define the boundaries.

The owner-approved partition retains all **10,728 variants**: **9,369 acceptance**
and **1,359 informational**, under the [S07-3 amendment](S08-acceptance-amendment.md).
No informational skip or rejected-option outcome can improve an acceptance
ratio. Current E2 evidence records **1.0** for types/symbols, errors and public
type display, with comparator, frozen-inventory, recursion and divergence checks
passing. Supplemental fixtures do not enlarge the denominator.

## Ownership and recursion

The checker operates under an exclusive operation scope, owns its merged
symbols, and retains the program behind escaped results. E2 exercises actual
checker/relation/printer recursion and reentry paths; the S04/S06/S07 E3 groups
remain separate from the S08 merge assertion.

`scripts/s08_ownership.py` composes the existing E3 producer with the production
`p2_checker` executable in debug, release, strict-provenance Miri and
AddressSanitizer with rebuilt std. It reads the authenticated native P2 archive
and projects it to one independent primitive program plus **all four merge
schedules**: single checker, repeated forward/reverse queries, separate
checkers, and concurrent first construction/query behind a barrier. Each
schedule creates its own program/checker; no merge actions are dropped.

The comparison checks shared bound-file identity, unchanged original symbol
graphs, distinct checker-local symbols and types, exact native declaration and
property results, repeat identity, and successful queries from B after A and
its program are released. The control program additionally verifies retained
result lifetime. False, unsupported, missing or malformed observations cannot
pass. `run.e3.independent_checker_merges` requires all four instrumentation
outcomes; it does not certify the remaining S09 ownership scenarios. Miri host
I/O is enabled only because the existing example reads requests and writes
observations; strict provenance and memory validation remain enabled.
