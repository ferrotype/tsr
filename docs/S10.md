# S10 embedding interfaces

Implementation and acceptance are separate: the adapters are executable, while
E7/E8 consume authenticated captures and retain any failed performance gates.
The [implementation plan](S10-implementation-plan.md) defines the workload,
ownership contracts, build commands, and measurement intervals.
The [initial acceptance results](S10-results.md) record full correctness and
ownership passes and the three remaining performance gaps.

## Rust

`tsr_embed` exposes parser functions without its default `checker` feature.
`parse` returns an immutable unbound `AstFile`; `parse_and_encode` returns owned
protocol-8 bytes with the content hash used by the pinned API server. Input is
already-loaded source bytes; physical-file BOM/encoding conversion belongs to
the host. Supply canonical file names and parse options explicitly.

With `checker`, construct a `Session` using `ProgramOptions`, an explicit host,
a `FileCache`, and `Counters`. `MemoryBuilder` plus `BundledFs` supplies a fully
in-memory program including standard libraries. The session owns one program
and lazily initializes its checker on the first operation.

```rust,ignore
let session = tsr_embed::Session::load(options, &mut cache, &counters)?;
let file = session.program().file(b"/main.ts").expect("loaded file");
let mut operation = session.operation()?;
let diagnostics = session.program()
    .semantic_diagnostics_with_checker(&mut operation, file)?;
```

Use the operation's existing `retain_type`, `retain_symbol`, and
`retain_signature` APIs for results that outlive the operation. They retain the
exact checker/program and reject import into another checker generation.
Dropping a session releases its ownership; an independently retained result
remains valid. `retire()` explicitly prevents subsequent queries, including
queries through retained results. Reentry fails before waiting. Native unwinding
retires the active generation while preserving the panic payload.

`tools/s10/rust-consumer` has an independent manifest and lockfile. It constructs
through this public API and runs S08's existing baseline visitor. It is not a
workspace example or a second checker implementation.

## Bare WebAssembly

Build `tsr_wasm` as parser-only or with `checker`. The parser release uses the
pinned Binaryen post-link optimizer. The separate `corpus` feature
is a capture adapter, not part of the shipped checker API. Generated bindings
are wrapped in a factory, so each instance has independent globals and can be
released. Use `tools/s10/wasm/instance.mjs` rather than retaining generated raw
handles yourself.

```javascript
import { createBindings } from "./bindings.mjs";
import { createInstance } from "./instance.mjs";
const module = await WebAssembly.compile(wasmBytes);
const compiler = createInstance(createBindings, module);
const bytes = text => new TextEncoder().encode(text);
const host = compiler.createHost(bytes("/"));
host.addFile(bytes("/main.ts"), bytes("const value: string = 1;"), true);
const session = host.compile({ strict: true, noLib: true });
console.log(session.diagnostics());
console.log(new TextDecoder().decode(session.typeAtPosition(bytes("/main.ts"), 6)));
session.dispose();
compiler.dispose();
```

Host compilation consumes the host builder. `addFile` accepts physical bytes;
`addDirectory` and `addSymlink` complete the input snapshot. `compile` takes the
compiler's raw numeric-enum options format, not tsconfig's string-valued enums.
There is no fallback to the surrounding machine's filesystem.

Parser calls accept loaded byte arrays, a byte filename, script kind, and
optional JSX/external-module indicator booleans. Results are copied owned arrays,
not views into wasm memory. Type query offsets are UTF-16; diagnostic ranges
are UTF-8 byte offsets and diagnostic strings are byte arrays, preserving the
source's WTF-8 behavior.

Ordinary Rust API errors throw `WasmApiError` without retiring the instance or
its other sessions: unknown files, invalid positions/options and queries on a
retired session are recoverable. A failed `compile` still consumes its host;
JSON serialization failures before the Rust call leave the host usable. Rust
errors use a private tagged ABI response, rather than treating arbitrary JS
exceptions as recoverable.

Traps and unclassified exceptions (including engine stack-overflow `RangeError`)
make the wrapper terminal. It detaches automatic JS finalizers without calling
Rust destructors and releases its instance references. Create a new instance
after such a failure. Outputs copied by earlier successful calls remain valid.
Native unwinding and native
thread contention are not claimed for wasm. The engine's call-stack limit
remains distinct from growable linear-memory stack segments. The validated Node
host uses `--stack-size=4096` (4 MiB); default Node overflows on two frozen stress
cases. Other JS engines, including browser defaults, need their own stack
validation. This is an explicit host configuration, not a corpus exclusion.

## Native Node adapter

`tsr_node` is a Node-API leaf. Build with `scripts/s10_build.py --node`; load
`target/s10/node/tsr_node.node`. Its explicit parser object keeps one reserved
parser worker alive for a sequence of synchronous calls:

```javascript
const { Parser } = require("./tsr_node.node");
const parser = new Parser();
try {
  const encoded = parser.parseAndEncode(
    Buffer.from("const value = 1;"), Buffer.from("/main.ts"), 3);
  // encoded owns its bytes and remains valid after parser.close().
} finally {
  parser.close();
}
```

Every request creates and disposes its own AST. Only owned Rust inputs/results
cross the worker boundary. `close()` disconnects and joins the worker, and Node
finalization also closes an abandoned object. The convenience top-level
`parseAndEncode` performs a standalone call without a persistent worker.
Both entry points accept optional fourth `jsx` and fifth `force` boolean
arguments for external-module detection, defaulting to false as in the wasm
adapter. Script kind selects TSX parsing independently of these options.

The E8 socket comparison uses the pinned real `--api` server. It forces a new
source snapshot, fetches the source-file encoding, and releases that snapshot.
That interval includes loading/binding, JSON-RPC and base64 transport as well as
parsing/encoding. The in-process interval includes the synchronous worker request
and Node buffer transfer. Both paths must return identical protocol bytes for
every timed input. Neither may reuse an AST for unchanged text.

## Evidence

`python3 scripts/s10.py e7` and `e8` replay existing captures; they never launch
a benchmark implicitly. The registered `cargo xtask run e7/e8` commands bind the
resulting metrics and capture identities to repository provenance. Missing,
partial, changed or stale evidence cannot pass. Thresholds remain in
`status/experiments.toml`.

The capture source manifest is `tools/s10/sources.json`: the S10 crates' local
dependency closure, shared E2 corpus adapters/oracle and frozen inputs, S10
tools, compiler configuration and threshold ledger. E7/E8 use that same scope
plus their tracker wrapper and upstream gitlink. Unrelated crate, script, tool
and result-file changes no longer invalidate S10 evidence. Tests check the
local dependency closure, capture/ledger agreement and unrelated edits.
`cargo xtask run selftest` discovers both `scripts/tests/test_*.py` and
`scripts/test_*.py`, deduplicating legacy discovery shims by test identity.

Raw captures live under `target/s10`: `wasm-corpus`, `rust-corpus`, `lifetime`,
`portable`, `parser-measurement`, and `node-measurement`. Each preserves executable
and glue identities, inputs, raw observations and source stability. Corpus
captures authenticate and reference the already preserved native E2 output;
archive that referenced native file along with an exported capture.
