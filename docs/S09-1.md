# S09-1: retained checker results and checker-created AST

## Scope

Two E3 criteria: `checker_result_retention` (symbols note, section 3) and
`checker_ast_retention` (ownership note, section 4, and symbols note,
section 3). The handles themselves came with S08 P1: `RetainedType`, `RetainedSignature`,
`RetainedSymbol`, `RetainedNode` and `RetainedTypeList` each hold the exact
`Arc<CheckerOwner>`, and import rejects any other owner before a read. What S08
proved on a bare owner, this slice proves where the contract is actually
exercised: a pool lease ends, the idle slot is replaced, the pool goes away, and
the result is the only root left.

Every scenario runs over a program-backed pool (`CheckerPool::for_program` with
the real `ProgramCheckerHost`). "Dependencies" therefore means the bound file
set, and the tests watch a `Weak<Program>` next to the `Weak<CheckerOwner>`.

## Production changes

Both are in `crates/tsr_checker/src/handles.rs`; checker algorithms are untouched.

- `retain_symbol_ref` and `import_symbol_ref`. `retain_symbol` accepts only a
  symbol in the checker's own arena, so a symbol a query returned, which lives
  in the bound file, could not be retained at all. The new pair retains the
  `SymbolRef` form the queries return and imports it back as one. Exact-owner
  rejection matters more here than for types: two checkers over a shared file
  hold the same `SymbolId`, and only the owner check separates them.
- `synthetic_expression_at(parent, type, is_spread)` and `node_parent`. The pin's
  `createSyntheticExpression` always takes a parent; the public operation only
  offered the parentless form, so the file-parent half of the criterion had no
  surface. The new entry goes through the existing port
  (`synthetic_call_argument`), and `node_parent` reads the link back through the
  checker's own arena or its retained file set.

## Suites

`data/s09/ownership-cases.json` (version 3) inventories nine tests in
`crates/tsr_project/src/retention.rs`, scored apart from the S09-4 suites so a
regression names the contract it broke.

`retention::results::` (five tests, `checker_result_retention`):

- A type, a signature, a file symbol and an immutable type list outlive the
  lease with the exact checker identity, and a later checkout of the same slot
  is the same checker.
- Idle-slot replacement never rebinds them. The replacement answers the same
  query with the same numeric type slot and rejects all four handles, and an
  operation-scoped value of the old checker, with `WrongOwner`.
- Access reacquires the exact owner's permit: a second access on the holding
  thread is `Reentry`, the replacement checker runs freely meanwhile, and a
  reader on another thread is observed contending on the production permit
  (`observe_next_lease_contention`) before it proceeds.
- Retirement is not disposal: a retired generation refuses the operation while
  the result still holds the checker and its files.
- Final-drop order: with the pool gone, the checker and the program stay alive
  through each of the four results and a separate cache root, and both are
  released by the last one. Counters return to baseline in every test.

`retention::ast::` (four tests, `checker_ast_retention`):

- A parented synthetic expression resolves its type and its file parent (the
  `InterfaceDeclaration` it was given) after lease release and after idle-slot
  replacement.
- A signature resolves its synthetic declaration after the node builder
  releases its arena; the node that builder returned is rejected afterwards,
  which shows the two arenas are distinct.
- A sibling checker in the same pool generation, over the same program, with
  the same signature slot, rejects the node, the signature and every typed link
  read through them.
- Dropping the slot, the pool and every caller handle cannot free the storage
  while a node or signature is retained; the last retained handle releases it.

## Verification record

Both suites pass in debug, release, Miri with `-Zmiri-strict-provenance`, and
AddressSanitizer with a rebuilt std, using the producer's exact command form
(`--lib --locked <filter> -- --test-threads=1 --nocapture`). The existing pool
suite still selects exactly its nine tests. Two mutations confirm the suites can
fail: with the exact-owner import check disabled, the replacement and sibling
rejection tests fail; with the synthetic parent link dropped, the four AST tests
fail.

The producer publishes `checker_result_retention` and `checker_ast_retention`,
each requiring its suite in all four modes, plus per-mode outcomes and
`checker_retention_tests`. A retention failure does not falsify S09-4's
criteria, and an S09-4 failure does not falsify these. The aggregate `miri` and
`address_sanitizer` metrics fold the new suites in automatically. The three
producer test suites pass 48 Python tests. Changed-crate clippy with warnings
denied, formatting and `cargo xtask validate` pass.

No E3 evidence is recorded by this change: the registered capture and status
regeneration belong to the P8-style refresh, and this branch's other E3 records
are stale from the rebase onto S08 P7. S09-2, S09-3 and S09-5 remain open.
S09-3 stays blocked as its record says, on positioned printing and the
formatter, which the roadmap assigns to Phases 3 and 5.
