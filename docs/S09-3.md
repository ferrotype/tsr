# S09-3: request-owned API printing

## Scope decision

S09-3 requires both printing and insertion formatting. This increment implements
the printing ownership path over the existing printer slice. It does **not**
complete `exp.E3.api_scratch_disposal` or mark S09-3 done.

The owner requested that missing printing components be included only if they
belong to S09. The roadmap assigns complete printer parity to Phase 3 and the
formatter to Phase 5. Rust currently has neither the positioned-printing helpers
nor an indentation/formatting engine. Those ports remain outside this PR. No
threshold, criterion or sprint dependency changes to accommodate the gap.

## Plan and contract review

1. Compose the pinned `handlePrintNode` path: protocol-8 decoding, a fresh emit
   context and printer, and independently owned output bytes. Its three printer
   options map directly to Go. Base64 decoding and transport error framing stay
   with the later wire server.
2. Use the decoder's exclusive `AstBuilder` as the real request scratch owner.
   Do not publish an `AstFile`, copy into a generic test arena, or register node
   handles. A decoded nil root panics, as observed from Go's `Printer.Emit`.
3. Scope all decoded nodes, emit metadata and writer storage to the call. Check
   release on output, decoder error, unsupported printer input and decoder panic.
   Keep output alive after scratch destruction and repeat printing alongside an
   existing snapshot registry to detect retained roots or session arena growth.
4. Freeze a small independent Go encode/decode/print observation set, including
   supported outputs and named Rust boundaries. Execute the ownership assertions
   in debug, release, Miri and ASan. Report printing separately from the broader
   S09-3 criterion.

Printing requires no checker identity, lease or snapshot in upstream. The Rust
entry point therefore accepts wire bytes and returns bytes directly. A caller
doing work on behalf of a snapshot can use its request panic boundary and commit
those bytes through the existing generation gate. Printing runs before taking
publication locks; only bytes enter `PublishedResult`. The request never extends
the lifetime of its synthetic syntax to the session.

Malformed decoder inputs retain their existing returned-error/panic behavior.
This wrapper does not add wire validation or recovery semantics of its own.
`Snapshot::request` retires its generation when a panic crosses that boundary;
an ordinary unsupported printer result does not retire it. The existing decoder
watchdog requirement for malicious sibling-chain cycles remains with transport.
The native probe corrected an initial source-only assumption about nil roots:
Go panics with a nil dereference, so Rust explicitly panics with
`nil root passed to API PrintNode`. Tests compare the failure class and both
diagnostic messages; they do not accept an arbitrary panic as parity.

## Insertion formatting

The dependency described below is now in the tree: the formatter port
(`docs/S09-3-formatter-plan.md`, steps F0 to F7) brought token navigation, the
formatter, the statement printer, positioned printing and the API function.
`tsr_api::format_node_for_insertion` owns the decoded tree, the positions assigned
to it, the synthetic source file over the printed text, the formatting scanner
and the edit list. The target file is borrowed and only read. Six disposal tests
mirror the printing ones, against frozen native rows, and the producer publishes
`api_scratch_disposal` as printing and insertion formatting together in all four
modes. Two of the printing fixtures recorded Rust boundaries that no longer
exist, statements and preserved source newlines; they now expect the native
text, and a thirteenth case covers a statement kind the pinned printer panics
on, which Rust returns as an error with the same text.

No E3 evidence is recorded by this change. The section below is kept as the
record of what was missing when printing landed.

## Remaining dependency

Pinned `handleFormatNodeForInsertion` calls `PrintAndPositionNode` with position
callbacks, clones the positioned tree, builds a synthetic source file, converts
the target UTF-16 position, computes indentation, applies formatting rules, and
returns bulk-edited text. Rust lacks those components. `PreserveSourceNewlines`,
which positioned printing always enables, is also an explicit printer boundary.
Prefixing printer output with whitespace would not implement this contract.

When that formatter exists, add its actual decoded and positioned trees to the
request owner, freeze native insertion outputs, and extend the disposal tests.
Only then can the combined `api_scratch_disposal` metric pass. The current
`api_print_scratch_disposal` metric is informational and has no sprint consumer.

Tracked counters cover arena owners and storage allocations, not all heap calls,
writer buffers, `HashMap` bookkeeping, or RSS. They are paired with actual
registry membership assertions; no whole-process memory claim is made.

## Review and verification record

The independent review requested two changes, both applied: the decoder panic
fixture now mutates a type-literal root so bottom-up decoding allocates its
children before failure, and E3 verifies the native fixture's request/source
hashes and row identities before running Rust. A changed request cannot receive
fresh evidence by replaying old wire bytes. Failed fixture verification blocks
the printing metric and instrumentation aggregate, while the independently
measured S09-4 criteria keep their own outcomes.

The 12 native observations contain six successful text results, two successful
Go requests that hit explicit Rust printer boundaries, two returned decoder
errors, and two classified panics. They are measured through the actual pinned
encoder, decoder and printer with Go 1.27.1 and `GOTOOLCHAIN=local`; the JSON and
overlay sources are under `data/s09/printing-*` and `tools/s09`.

Five Rust ownership tests exercise those observations, live decoded storage,
sixteen repeated snapshot-backed publications, populated decoder unwind, and
printer-error cleanup. Debug tests, API clippy with warnings denied, Rust 1.96
checks, formatting and tracker validation pass. The producer/provenance suites
pass 46 Python tests. The four native CI targets enforce the separate printing
metric; this record does not claim remote CI execution.

### PR review fixes, 2026-09-19

The formatter and token navigation initially exhausted a caller's 512 KiB
native stack on deeply nested parsed input, in both debug and release. The
two tail-recursive token searches now iterate in the pinned visit order.
Formatter descent and completion checks use ADR 0011's stack-growth policy
(128 KiB red zone, 2 MiB segments). Small-stack regressions cover 12,000-level
navigation and completion, plus 2,048-level document formatting; the formatter
tests observe actual stack growth rather than merely accepting successful exit.
All 14 navigation/formatter tests pass in debug and release, and changed-crate
Clippy passes with warnings denied. All six API insertion-scratch tests also
pass in debug and release, including native outputs and error/panic cleanup.

E3 now fingerprints the formatter, navigation and other missing executable
dependencies, its insertion fixture pair, and the native formatting overlay.
A regression expands the actual git pathspecs and checks the local dependency
closure of the ownership test packages. CI requires the combined printing and
insertion metric and all three checker retention metrics, and runs navigation
and formatter tests in both profiles on each enabled runner. A failure injected
into any S09 suite in any mode must falsify a metric that CI consumes. The 38
focused ownership, printing and formatting producer tests pass. This change
does not reuse the earlier E3 capture as evidence for the modified sources;
instrumented ownership outcomes must be measured again.
